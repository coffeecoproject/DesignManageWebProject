# 绩效前端浏览器验收证据（2026-07-17）

## 1. 范围

本证据仅覆盖前端会话内的绩效业务和当前消费者，不涉及后端持久化、权限、数据库、财务记账或税务处理。

验收链路：

```text
任务验收计分
-> 月度绩效草稿
-> 发布月度结果
-> 季度来源自动重算
-> 发布季度结果
-> 绩效看板 / 人员总览 / 薪酬明细读取
-> 当前账号员工端查看并确认结果
```

## 2. 运行环境

- Web：`http://127.0.0.1:5173`
- 浏览器：本机 Chromium Headless，通过 Chrome DevTools Protocol 执行真实 DOM 点击、键盘切换、SPA 路由切换、截图和控制台采集。
- 桌面视口：`1440 x 1000`
- 当前管理操作人：`李明`
- 当前员工端演示身份：`20260001 / 示例全职 A`
- 已覆盖绩效业务对象：`20260001 / 示例全职 A`、`20250018 / 示例全职 B`

浏览器插件在当前运行环境不可用，因此按前端测试技能约束使用本机 Chromium CDP；没有安装或修改项目依赖。

## 3. 正向交互结果

1. `/performance/monthly` 初始存在两名员工的 `2026-06` 月度来源；当前演示账号的最新有效来源由启动模型按正式发布领域函数初始化，其余结果仍按来源保持待发布。
2. 月度抽屉固定为 `结果概览 / 来源明细 / 操作记录` 三个 Tab；真实 `role=tab` 元素可获得焦点并通过键盘 `Enter` 激活`来源明细`，操作记录可通过鼠标切换。
3. 月度草稿显示任务质量分 `82 分`、任务完成分 `3.4 分`、月度绩效 `38.25 元`、月度预发 `19.13 元`。
4. 点击`发布月度结果`后，月度结果变为`已发布 V1`；季度来源从 `0/1` 自动重算为 `1/1`。
5. 季度计算金额为 `38.25 元`，季度预发合计为 `19.13 元`，结算差额为 `+19.12 元`；季度发布按钮由阻断状态变为可执行。
6. 点击`发布季度结果`后，季度结果变为`已发布 V1`，未出现第二套季度状态或自由结算日期。
7. 已发布季度结果可进入同一抽屉的更正模式；未填写更正原因或非零调整原因时，`发布更正版本`保持禁用。
8. 同一会话进入 `/performance/dashboard`，页面读取到 `38.25 元 / 19.13 元 / 82 分 / 1 条任务`。
9. 同一会话进入 `/people/overview`，`示例全职 B`的平均绩效为 `82`，来源仍是正式绩效结果。
10. 同一会话进入 `/salary/monthly`，已确认的 6 月薪酬快照没有被新发布绩效静默覆盖；反馈期内结果没有绕过门禁进入已锁薪酬。
11. 当前账号 `20260001 / 示例全职 A`的月度草稿由任务 `store-task-2026-008` 的验收计分生成，质量分 `88 分`、任务完成分 `2.2 分`、月度绩效 `24.75 元`、月度预发 `12.38 元`。
12. 管理端点击`发布月度结果`后，同一会话进入 `/my-work/performance`，只出现当前账号自己的 `2026-06` 正式结果，反馈状态为`待确认`。
13. 员工端打开共享结果抽屉并点击`确认结果`后，反馈状态变为`已确认`；返回管理端打开同一结果，抽屉同步显示`已确认`。
14. 原始浏览器脚本没有直接写入正式结果，只执行页面已有的发布和员工确认动作；后续回归另用全新浏览器会话验证启动模型。
15. 全新浏览器会话直接进入`/my-work/performance`，无需先访问管理端即可看到当前账号`2026-06 / 绘图任务制V1 / 24.75 元 / 待确认`，列表共1条。
16. 全新会话打开共享抽屉可读取任务验收来源，点击`确认结果`后状态变为`已确认`；页面无框架错误覆盖层。
17. 另一全新浏览器会话从员工确认开始继续执行薪酬链路；月度绩效结果金额为`24.75 元`，薪酬仅承接规则约定的50%月度预发，即`12.38 元`，没有把结果总额重复计入工资。
18. 薪酬确认前置依次通过个税资料、考勤月报、社保和公积金；其中考勤月报确认时间会晚于该员工当月最新人工调整，确认后状态立即变为`已确认`并被薪酬读取。
19. 全部来源确认后，`20260001 / 示例全职 A`的薪酬由`结算中`变为`待确认`，应发工资为`8,512.38 元`、扣减为`2,643.91 元`、实发工资为`5,868.47 元`，抽屉明确展示`绩效预发 12.38 元`。
20. 点击`确认薪酬`后，薪酬列表状态变为`已确认`；管理端绩效明细中同一`2026-06`正式结果的生命周期同步变为`已结算`。
21. 员工端列表继续显示`反馈状态=已确认`是既定字段语义，不代表绩效尚未结算；结算状态以管理端绩效生命周期和薪酬结算引用为准。
22. 本轮发现并修复了考勤确认时间早于当月人工调整、导致页面提示成功但确认立即失效的问题；领域测试已覆盖“确认时间必须位于最新调整之后”。

## 6. 业务闭环复查证据

- 复查结论：在当前明确启用的`绘图任务制`和前端会话范围内，`规则自动适用 -> 线下签署档案 -> 任务验收计分 -> 月度结果 -> 员工反馈期限 -> 季度结果 -> 薪酬消费 -> 看板及人员摘要`正向链路成立；更正、异议阻断、版本差额和已锁薪酬不回写的反向边界成立。
- 任务验收按执行人、验收所属月和当期有效规则解析历史版本，不再读品牌当前版本。
- 月度来源强制校验验收计分操作人、操作时间和操作记录；缺少验收证据的计分不进入绩效。
- 季度发布同时阻断未发布月份和存在未处理异议的月度结果。
- 季度人工调整录入错误可生成新版本，不要求月度来源先发生变化。
- 有异议的已发布结果保留在绩效异常摘要，但不进入常规趋势、人员平均绩效、人员风险结论或任务候选软提示。
- 员工端读模型严格按当前账号工号匹配，不再回退到第一个在职人员。
- 签署档案只证明线下文件已归档，不控制规则适用、计算或发放；系统没有新增员工规则确认或额外审批流。
- 当前不支持的绩效类别不会生成结果或进入薪酬，避免用静态 Mock 假装业务已闭环。

## 7. 证据边界

- 当前账号已具备完整来源 Mock，因此浏览器已覆盖发布和员工确认；异议、超期、异议处理和更正继续由可执行领域测试覆盖。
- 当前演示正式结果不是手写金额快照；每次应用启动均从规则适用、任务验收、计分来源、人员和工作日历重新构建草稿，再调用正式发布领域函数生成。
- 任务验收自身的计分更正入口不属于本轮绩效前端范围。若验收事实被正式更正，绩效能够按新来源生成后续版本，但本轮不声明任务模块的逆向业务已经重构。
- 前端状态为会话状态。刷新页面会重建演示正式结果并恢复为待确认，不保留上一会话的确认或异议状态，不代表生产持久化。
- 本证据证明的是当前前端业务与跨页面读取，不是权限、后端并发、审计级持久化或生产可用性证据。
