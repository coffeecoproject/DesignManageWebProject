Performance rule internal field keys are retained for later calculation/API design only. The business UI may expose rule-version and rule configuration concepts such as template/category, workflow status, applicable positions, effective period, uploaded corresponding file, system-generated rule file, task score, unit, confirmation requirement, quality dimension, weight, ratio, handling method, business calculation parameter, formula input item, formula expression, and formula output result. Rule names and generated file names are system-derived as `{规则模板}V{版本号}`, for example `绘图任务制V1`; status and position scope belong to separate fields, not the name. Performance rules in this module apply only to full-time personnel and may cover multiple full-time positions. For the current `绘图任务制` template, task items, quality dimensions, and formula structure are fixed modules; value parameters can be adjusted while task/quality/formula structure changes require a new template decision. Rule workflow status is `草稿 -> 审核中 -> 待发布 -> 已发布`, with退回 returning to `草稿`. One position or employee may match multiple performance categories, but one employee + one category + one effective period must execute only one version. Employee confirmation, current/pending/execution version, old-version continuation, and payroll usability by employee belong to the performance signature prototype, not the rule row. The business UI must not expose internal rule codes, task type codes, score field keys, rule parameter keys, task event keys, or monthly result keys.
