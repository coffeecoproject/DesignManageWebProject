# 前端四条业务链验收追踪

更新日期：`2026-07-18`

状态：`frontend_session_verified_with_explicit_boundaries`

## 1. 范围

本表统一追踪以下四条前端会话业务链：

1. 客户任务收入。
2. 全职员工成本。
3. 兼职自然人劳务。
4. 员工费用报销。

“通过”只表示当前 React 状态容器、领域模型和可执行测试能够完成对应链路，不代表后端持久化、数据库事务、服务端授权、正式税务申报或生产财务合规已经完成。

## 2. 统一验收口径

每条链必须同时核对：

```text
业务输入
-> 领域事实
-> 应收或应付
-> 实际收付款及复核
-> 会计凭证与总账
-> 税务影响（适用时）
-> 撤销、冲正或重新提交
-> 重复与越权边界
```

普通单测总数、页面能打开和 Mock 能展示均不能单独证明链路闭合。

## 4. 共享状态与事实身份

- 费用提交与审核使用同一 `MyExpenseReviewProvider` 会话状态，不再维护两套互相漂移的报销记录。
- 财务流水按流水号幂等写入；应收应付结算状态从有效已入账流水及冲正净额推导。
- 合同收款概况与记录从携带同一 `contractId` 的已确认应收及有效已入账收款派生；待复核不计入，冲正按净额回退并保留历史记录。
- 客户结算事实、兼职劳务事实和应收应付使用稳定来源身份；撤销后重新验收不新建第二条业务事实。
- 薪酬核定保存结算快照；考勤源在核定后变化会主动使薪酬退回待确认，而不是静默保留旧结果。

## 5. 明确未闭合边界

| 边界 | 当前事实 | 阻断影响 |
| --- | --- | --- |
| 服务端权限 | 路由与菜单尚无真实登录身份和服务端授权守卫 | 不能声明员工无法通过直接 URL 访问管理或财务页面；属于后端接入前的安全阻断项 |
| 持久化与并发 | 所有业务状态仍为前端会话内存 | 不能证明刷新恢复、并发幂等、事务回滚或数据库唯一约束 |
| 文件重复识别 | 报销重复控制使用业务字段和附件名称 | 无文件内容哈希，不能覆盖改名文件或跨设备并发提交 |
| 正式外部结果 | 银行、电子税务局、对象存储和回执解析未接入 | 当前凭证、对账、申报及回执仅能证明前端流程与口径 |
