# 税务办理补退与更正前端验收追踪

## 范围

本追踪表覆盖税务办理完成申报后的共同结算链路：缴款、更正申报、差额补缴、多缴退税、同税种抵缴、税费流水和会计凭证。它用于证明不同税种共用的办理状态和金额口径一致，不替代个人所得税、增值税、企业所得税和印花税各自的专项验收。

## 统一口径

- 正常申报和每次更正都保留独立版本，历史申报结果不得被覆盖。
- 更正后的 `应缴` 或 `应退` 是本次版本相对上一版本的差额，不是重新结算全部申报金额。
- 实际缴款和退税到账必须携带日期及回执，并先生成待复核收支流水。
- 多缴税款可以申请退税，或在同一税种后续应缴事项中抵缴；不同税种不得直接互抵。
- 抵缴不产生银行收支流水，只更新多缴来源和目标税款的结算事实。
- 增值税及附加的缴款、退税必须按增值税、城建税、教育费附加、地方教育附加分项进入会计凭证。
- 个人所得税月度累计预扣出现负数时，不由企业办理当月退税；依照年度综合所得汇算处理。

## 完成判定

每个编号必须在已注册测试模块中真实执行并通过。仅有页面展示、Mock 状态、类型检查或人工说明不能作为验收通过证据。税种专项规则与本共同链路冲突时，以税种专项规则为准，并必须补充相应自动测试。

## 当前边界

- 本轮只覆盖前端领域模型、页面交互、Mock 和自动验收，不包含电子税务局接口、后端事务、数据库持久化或生产数据。
- 退税、抵缴和更正的正式结果以电子税务局回执为准；前端只登记外部结果，不新增内部审批流。
- 抵缴首版限定同税种事项，避免在没有税务机关确认依据时将不同税种余额自行互抵。
- 会计凭证记账与总账承接仍是前端会话态；本追踪只证明领域计算和状态门禁一致，不代表后端持久化、并发控制或审计级总账已经完成。
