# 自然人付款与个税前端验收追踪表

更新日期：`2026-07-14`

## 1. 目的

本追踪表是 `NP-01 ~ NP-20` 的验收事实来源。验收不得再以页面可见、Mock 已拼接、测试文件存在、测试名称存在或普通单测总数通过替代完整前端业务链证据。

每个验收项按以下阶段核验：

```text
真实业务输入
-> 领域计算
-> 跨模块状态变化
-> 会计结果
-> 申报结果
-> 冲正或更正
-> 自动测试证据
```

不适用于具体场景的阶段必须明确标记 `N/A`，不得用缺省值代替。只有所有适用阶段均由实际执行并通过的测试覆盖，才可标记为 `前端链路通过`。

## 2. 证据等级

| 等级 | 定义 | 是否可声明业务闭环 |
| --- | --- | --- |
| `模型通过` | 直接调用纯函数验证计算、校验或转换 | 否 |
| `模块通过` | 验证单一状态容器或模块内状态变化 | 否 |
| `跨模块通过` | 由前置业务动作驱动至少两个模块的真实状态变化 | 否 |
| `前端链路通过` | 适用的输入、状态、会计、申报和反向链路均有可执行证据 | 是 |

`前端链路通过` 只评价浏览器前端现有领域状态和派生链路，不代表数据库持久化、事务、幂等、并发、权限或正式申报接口已经闭环。后端持久化闭环必须另有 API、数据库和服务测试证据，不与本表混算。

`apps/web/scripts/natural-person-payment-acceptance.mjs` 只接受测试运行器实际返回的已执行、已通过场景，不再读取源码搜索测试名称。当前门禁只输出验收编号覆盖数、实际通过的具名场景数和前端完整链路数；在阶段断言与具体测试建立可执行绑定前，不允许由元数据推导链路闭合。

当前结论：验收编号覆盖 `20/20`，前端场景闭合 `20/20`。具名场景数量以 `test:web` 的实时门禁输出为准，不在文档中固化。每个编号的闭合范围以本表“真实输入与目标结果”为边界；依赖的后续支付、申报或会计步骤由对应编号交叉承接，不重复伪造全链路。前端闭合只由带 `FRONTEND-CHAIN` 标识且实际执行通过的生产工作流测试产生。后端持久化闭环仍为 `0/20`，明确不在本轮前端范围内。

### 工资薪金专项门禁

以下规则属于 NP-19 工资薪金链路的细化门禁，不新增验收编号，也不得只靠页面 Mock 证明：

| 规则 | 可执行场景 |
| --- | --- |
| 低收入简化预扣必须具备完整资格，且全年 6 万元不得重复扣除 | `salaryDomain.test.ts`：`applies the 60000 annual basic deduction only after low-income eligibility is confirmed` |
| 本年首次就业必须保存首次就业月份和佐证 | `salaryDomain.test.ts`：`requires retained evidence before first-employment cumulative deduction enters payroll` |
| 实际付款跨越原核定月份时先阻断，重新核定后才允许确认发放 | `salaryDomain.test.ts`：`recalculates delayed salary by the actual payment month before confirmation` |
| 工资应付登记、复核及薪酬回写必须沿用同一工资单号 | `salaryFinanceFrontendWorkflow.test.ts`：`NP-19 FRONTEND-CHAIN registers, reviews and binds the net salary payment through one payroll number` |
| 考勤源变更必须使已确认薪酬退回待确认；已发放月份禁止直接改考勤源 | `salaryDomain.test.ts`：`invalidates confirmed salary when attendance sources change and blocks paid months`；`peopleDomain.test.ts`：`derives every affected salary month from a cross-month attendance record` |

上述场景随 `test:web` 实际执行；任一失败时不得声明工资薪金个税前端链路完整。

### 申报后半链路专项门禁

以下规则约束确认快照、正式申报、更正生效和会计勾稽，不增加新的验收编号：

| 规则 | 可执行场景 |
| --- | --- |
| 已确认申报准备发生人员身份或扣缴事实变化时必须重新准备，不得沿用旧快照 | `financeTaxMatterModel.test.ts`：`requires confirmed personal income tax preparation before tax handling` |
| 个税正式申报金额必须与已确认人员明细合计一致，不允许用任意外部总额覆盖人员扣缴事实 | `financeTaxMatterModel.test.ts`：`rejects IIT declaration totals that are detached from confirmed person-level details` |
| 更正申报完成后必须将待更正人员明细提升为有效快照，并清除待更正状态 | `naturalPersonPaymentFrontendWorkflow.test.ts`：`NP-15 FRONTEND-CHAIN preserves filed labor IIT and automatically opens one correction version after posted reversal` |
| 个税办理事项不重复计提负债；实际缴税只借记 `2221.03` 并贷记银行存款 | `financeAccountingVoucherModel.test.ts`：`does not accrue IIT twice and clears the withholding liability through the actual tax payment` |

上述场景与 `NP-15`、`NP-19` 共同构成个税申报后半链路证据。任一失败时，只能声明上游计算可用，不得声明确认、申报、更正和会计清偿闭环。
