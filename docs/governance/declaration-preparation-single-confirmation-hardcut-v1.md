# 申报准备单次确认硬切方案 V1

## 目标

将增值税、企业所得税和个人所得税的申报准备统一为“来源检查、正文核对、最终确认”流程，删除准备项行级确认和跨模块跳转，避免同一申报结果被重复确认。

## 目标流程

1. 上游业务模块形成薪酬、发票、应收应付、总账和税务办理事实。
2. 申报准备自动读取来源事实并生成税额或汇算测算。
3. 未完成的来源事实只作为阻断事项展示，不在本页修正，也不提供跨模块跳转。
4. 用户在抽屉正文核对测算结果和调整明细。
5. 无阻断事项时，使用抽屉底部唯一确认动作固化当前来源快照和测算结果。

## 税种边界

- 增值税及附加：正文展示申报销售额、专票与其他销售额、未开票收入、红票冲减、税率口径、增值税及附加测算；红票、后续开票和未开票税额基础异常作为来源阻断。
- 企业所得税季度预缴：正文展示累计利润、纳税调整、小型微利资格、已预缴和本期预缴测算；不再逐行确认纳税调整或预缴口径。
- 企业所得税年度汇算：正文展示年度调整明细和应补或多缴测算；年度结账、正式报表和第四季度预缴仍是来源阻断。
- 个人所得税：正文展示薪酬与员工预扣明细；薪酬未确认时阻断，准备页不修改薪酬或扣除资料。

## 不兼容清理

- 删除准备项“操作”列。
- 删除 `关联发票`、`完善税务口径`等准备页跨模块跳转。
- 删除行级 `确认调整`、`确认预缴口径`、`确认汇算口径`等状态与操作记录。
- 计算项改为只读测算结果；只有真实来源问题使用`待确认`阻断最终确认。

## 验收标准

- 增值税、企业所得税、个人所得税准备项均无行级操作。
- 来源完整时，底部最终确认可直接使用。
- 来源不完整时，阻断事项可见且底部最终确认禁用。
- 企业所得税调整明细和预缴或汇算金额在正文可核对。
- 确认后保存来源快照；来源变化后记录回到`准备中`，但不恢复旧的行级确认流程。
- `typecheck`、Web 单元测试、lint 和 Web build 通过。

## 当前边界

本轮为前端会话状态和 Mock 契约硬切，不代表电子税务局提交、后端持久化、税务审批或法定申报证据已经接入。
