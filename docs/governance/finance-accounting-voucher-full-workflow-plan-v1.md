## 0. 当前硬切口径（2026-07-10）

独立`发票匹配`页面、路由和待办已由`docs/governance/invoice-association-hardcut-v1.md`取代。当前只保留发票台账与应收应付共用的发票关联抽屉；本文后续历史记录若仍使用旧模块名称，不作为当前实现依据。

以下口径覆盖本文较早阶段记录中“未完成银行对账即不能进入待记账”的试验性描述：

- 账套启用期间是会计凭证、总账、期间结账和财务报表的最早期间。启用前的业务样例不进入会计账簿链路。
- 资金凭证以“流水已复核、来源单据完整、原始凭证完整、金额和科目有效”为记账前提；`未对账`本身不再使资金凭证停留在`待生成`。
- 银行对账仍是月末结账的独立阻断检查。对账异常，或已标记对账但缺少银行关联依据，仍是资金凭证的问题状态。
- 三张表必须同时通过总账试算、资产负债表勾稽及异常余额检查、现金流量表勾稽，才能作为结账快照生成。前端会话内快照不等同于会计档案归档。

### 0.1 小规模税额与月末事项边界

- 小规模增值税不再以全局 `1%` 作为销项、进项、应收应付或未开票收入的默认税率。销项发票保留票面税率；应收收入先记录交易税务分类和`待申报判定`，申报准备按公司申报周期、销售额、交易分类和票面事实形成`免税 / 减按1% / 按法定征收率 / 不涉及`候选结果。
- 当前前端税务配置为按季申报，免税阈值和减征征收率均为有效期配置；最终税额仍必须以电子税务局申报结果与回执冻结，不能把前端候选结果当作申报事实。
- 小规模进项不生成进项抵扣；票面税率只作为原始凭证与成本费用依据，成本、费用或资产按含税金额处理。
- `资产与待摊`是折旧、摊销的来源台账：固定资产保存原值、启用日期、预计使用月数、累计折旧和原始凭证；待摊事项保存受益期间、已摊/未摊余额、本期摊销和原始凭证。`月末事项`只读取这些来源，确认后才生成待记账凭证。
- `月末事项`位于会计凭证之前，当前先承接有来源的固定资产折旧、预付/待摊分摊和合同验收收入确认。收入确认明确回看既有应收应付权责事实，不重复生成收入凭证。事项确认后生成待记账凭证，凭证记账后进入总账。
- 折旧、摊销、预收转收入、成本结转不得在期间结账页面手工填写或由结账页计算。期间结账只汇总`月末事项待确认`数量并导航到来源工作台。
- 当前公司按无存货型设计服务模式处理，项目外协和可直接归属项目的材料由应收应付/项目成本确认承接；不建设库存出入库和存货成本结转。未来发生实物库存时，必须先建设库存、领用和成本计量来源后再引入成本结转事项。

## 1. 目标

本方案用于把 `财务管理 / 会计凭证` 从早期前端凭证预览升级为完整的凭证生成闭环方案。

截至 2026-06-29，前端已完成状态硬切、发票税额接入、银行对账前置、银行对账来源关系、税务事项接入、前端会话内记账/冲销模拟和后端扩展契约。后续真实后端实现仍应做不兼容硬切，不保留早期 `草稿` 凭证口径，不继续让 `应收应付` 和 `收支流水` 直接 map 成最终会计凭证。

目标流程要覆盖：

- 应收应付形成权责事实。
- 发票台账提供进销项、税额和开票事实。
- 收支流水提供系统侧收付款事实。
- 银行对账提供银行侧真实发生事实。
- 会计凭证生成中心统一归集以上事实，生成权责凭证、资金凭证、税费凭证、调整凭证和冲销凭证。
- 后续总账、报表、月结只消费已记账凭证。

## 2. 依据和约束

已核对的公开口径：

- 财政部会计司官方解读指出，电子发票、财政电子票据、电子客票、电子行程单、银行电子回单等电子会计凭证逐渐普及，且会计凭证是单位进行会计核算的重要依据。参考：`https://kjs.mof.gov.cn/zhengcejiedu/202004/t20200402_3492561.htm`。

项目内已确认约束：

- 当前项目按湖北武汉小规模纳税人口径推进，增值税及附加方案已在 `docs/governance/vat-declaration-hardcut-plan-v1.md` 中固定。
- 小规模纳税人的进项发票用于成本凭证和内部核对，不作为增值税抵扣项。
- 税务最终申报和缴款结果以电子税务局实际办理结果、回执和缴款凭证为准。
- 当前前端仍是 mock 状态，不具备正式会计凭证、总账、月结、审计级归档能力。

因此，本方案不是法律或审计意见。它是项目内部前端和后续后端接入的业务系统设计基线。

当前前端生成方式：

```text
已确认应收应付 + 发票/未开票/无票事实 -> 权责凭证候选
已入账且已复核、原始凭证完整的收支流水 -> 资金凭证候选
已确认税务事项 + 税务回执/缴款事实 -> 税费凭证候选
已入账且已复核、原始凭证完整的流水冲正/补差、未解决红票等 -> 调整凭证候选
前端会话内制单 -> mock 正式凭证号 + 冻结正式凭证快照
前端会话内记账 -> 正式凭证快照派生记账影响
前端会话内冲销 -> 原凭证标记已冲销 + 追加反向冲销凭证快照
```

当前主要缺口：

- 前端状态和记账/冲销仍是会话内 mock，不是正式会计凭证。
- 会计凭证、凭证分录、来源关系、凭证号序列、期间锁定、事件记录和总账分录已有后端契约，但还没有真实后端持久化。
- 正式凭证号还没有由后端事务内序列表分配。
- 期间关闭和重开还没有真实权限、审批、审计和回滚边界。
- 三张表、总账、明细账和科目余额还没有消费真实 `已记账` 凭证。
- 正式后端 API、数据库 migration、contract tests、发布回滚和恢复演练尚未实现。

## 4. 目标业务分层

完整闭环必须区分以下层级：

```text
业务事实层
合同 / 项目阶段 / 报销 / 薪酬 / 外协 / 税费

权责确认层
应收应付 / 收入成本费用确认 / 往来确认

票税事实层
销项发票 / 进项发票 / 红字发票 / 未开票收入 / 税务申报准备

资金事实层
收支流水 / 流水复核 / 银行流水 / 银行对账

会计凭证层
权责凭证 / 资金凭证 / 税费凭证 / 调整凭证 / 冲销凭证

账簿报表层
总账 / 明细账 / 科目余额 / 三张表 / 月结
```

关键原则：

- 业务确认不是会计记账。
- 发票不是收款事实。
- 银行流水不是业务发生原因。
- 应收应付不是最终会计凭证。
- 会计凭证必须能追溯到来源单据、发票、银行流水和操作记录。

## 5. 目标总流程

本方案按三条事实线推进，最后进入同一套会计凭证体系。

### 5.1 权责线

权责线回答的是：

```text
这笔收入、成本、费用、往来是否已经应该确认？
```

目标流程：

```text
业务发生
  ↓
业务单据确认
  ↓
生成应收应付
  ↓
匹配发票、未开票收入、无票成本、报销单、结算单、工资表等业务事实
  ↓
生成权责凭证候选
  ↓
完整：待记账
不完整：待生成 / 需处理
```

权责凭证的核心来源是 `应收应付`，但不能只看应收应付金额。完整处理时还要看：

- 发票或未开票收入口径。
- 税额或免税/不计税口径。
- 原始凭证。
- 会计科目。
- 来源单据。

### 5.2 资金线

资金线回答的是：

```text
这笔钱是否真实进出公司账户？
```

目标流程：

```text
发生收款/付款
  ↓
生成系统收支流水
  ↓
流水复核
  ↓
导入银行流水
  ↓
银行对账
  ↓
生成资金凭证候选
  ↓
完整：待记账
不完整：待生成 / 需处理
```

本方案中 `资金凭证` 是项目内的业务分类名，用于表示现金、银行存款或对公账户资金变动形成的凭证。实际凭证种类仍可细分为：

```text
收款凭证
付款凭证
转账凭证
```

因此，用户口头说的“现金凭证”在本项目文档中统一称为 `资金凭证`；它的核心是银行存款、现金或对公账户资金事实。

### 5.3 票税线

票税线回答的是：

```text
这笔业务的发票、税额、申报和缴款口径是什么？
```

目标流程：

```text
导入或补录发票
  ↓
发票台账
  ↓
共享发票关联
  ↓
申报准备
  ↓
税务办理和回执
  ↓
影响权责凭证、税费凭证或调整凭证
```

发票既不是业务发生本身，也不是资金到账本身。它提供票据和税额事实，主要影响：

- 权责凭证中的收入、成本、费用和税额拆分。
- 税费凭证中的应交、实缴和结转。
- 后续开票、红票、未开票收入和申报差异调整。

### 5.4 统一凭证体系

权责凭证、资金凭证、税费凭证、调整凭证和冲销凭证不是不同账套。

它们最终都进入同一套会计凭证体系：

```text
权责凭证
资金凭证
税费凭证
调整凭证
冲销凭证
  ↓
统一会计凭证列表
  ↓
已记账后进入总账
  ↓
报表和月结
```

凭证类型只是 `会计凭证` 的分类字段，不代表多套账。

## 6. 会计凭证状态机

完整版本不再使用 `草稿` 作为主状态。目标状态如下：

```text
待生成
需处理
待记账
已制单
已记账
已冲销
```

### 6.1 状态定义

| 状态 | 含义 | 是否进入总账 | 是否允许编辑 | 典型来源 |
|---|---|---:|---:|---|
| `待生成` | 来源事实已经存在，但必要前置资料还没满足，系统暂不生成完整分录 | 否 | 不存在凭证编辑，仅处理来源资料 | 已复核流水但银行未对账、税务事项未完成 |
| `需处理` | 系统尝试生成凭证，但发现科目、金额、来源、票税、银行或原始凭证问题 | 否 | 不能直接改凭证，应回到来源模块处理 | 缺科目、缺原始凭证、发票金额不匹配、银行对账异常 |
| `待记账` | 候选分录和来源校验通过，可以生成正式会计凭证 | 否 | 不编辑候选本身，制单前仍以来源事实为准 | 权责、资金、税费、调整凭证候选完整 |
| `已制单` | 正式会计凭证已创建并取得凭证号，但尚未记账到总账 | 否 | 不直接改分录，应撤回或重新制单需有操作记录 | 会计人员完成制单 |
| `已记账` | 凭证已正式写入账簿消费边界 | 是 | 不允许编辑，只能冲销或补充调整 | 总账、报表、月结来源 |
| `已冲销` | 原凭证已被冲销凭证抵消，保留历史和关联关系 | 原影响被冲销 | 不允许编辑 | 红冲、错账更正、跨期调整 |

当前不引入单独的会计凭证审核状态。审核、复核或审批类诉求应前置到来源事实、权限控制、问题原因和操作记录中表达，不新增 `待审核`、`审核中` 或 `已审核` 凭证主状态。

### 6.2 允许流转

```text
待生成 -> 需处理
待生成 -> 待记账
需处理 -> 待记账
待记账 -> 已制单
已制单 -> 已记账
待记账 -> 需处理
已记账 -> 已冲销
已记账 -> 调整凭证
```

不允许：

- `已记账` 直接回到 `已制单` 或 `待记账`。
- `已记账` 直接修改分录金额、科目或来源。
- `已冲销` 再编辑。
- 银行对账或发票关联不得直接修改已记账凭证，只能触发调整或冲销。

## 7. 凭证类型

| 凭证类型 | 来源 | 生成重点 | 当前代码基础 |
|---|---|---|---|
| `权责凭证` | 应收应付、发票、未开票收入、业务确认单据 | 收入、成本、费用、往来确认 | 已有应收应付生成基础，但缺票税 |
| `资金凭证` | 已复核收支流水、银行对账、银行回单 | 银行存款和往来结清 | 已有收支流水生成基础，但缺银行强校验 |
| `税费凭证` | 申报准备、税务办理、缴款回执 | 应交税费、实际缴款、税费计提或结转 | 已接入税务办理事项，缴款资金凭证仍由收支流水生成 |
| `调整凭证` | 流水补差、会计调整、银行差异、跨期差异 | 补差、重分类、金额修正 | 已有流水冲正/补差基础 |
| `冲销凭证` | 已记账凭证更正 | 冲销原凭证影响 | 当前缺失 |

## 8. 权责凭证完整规则

### 8.1 应收收入类

来源：

- 合同应收。
- 项目阶段确认。
- 其他收入确认。

完整前置：

- 应收应付 `confirmationStatus = 已确认`。
- 来源单据完整：`documentNo`, `sourceNo`, `sourceTitle`, `counterparty`, `accountingPeriod`, `confirmDate`。
- 原始凭证完整：合同、阶段确认单、验收单或其他确认依据。
- 会计科目映射完整：应收科目、收入科目。
- 发票或未开票口径明确。

目标分录：

```text
已开票收入：
借：应收账款/银行存款       价税合计
贷：主营业务收入/其他业务收入 不含税金额
贷：应交税费                 销项税额或小规模应纳税额口径

未开票但纳税义务已发生：
借：应收账款/银行存款
贷：主营业务收入/其他业务收入
贷：应交税费
并关联申报准备中的未开票收入处理记录

未达到收入确认条件：
不生成权责凭证，停留在待生成或业务模块
```

项目小规模口径说明：

- 销项发票仍用于确定不含税销售额和税额。
- 是否免税、是否申报、是否产生实际缴款，以申报准备和税务办理结果为准。
- 不应把含税收款直接当成收入金额。

### 8.2 应付成本费用类

来源：

- 员工报销。
- 外协结算。
- 材料采购。
- 运营费用。

完整前置：

- 应付已确认。
- 报销单、结算单、采购单、发票、收据或其他原始凭证完整。
- 费用或成本科目映射完整。
- 往来科目映射完整：应付账款、其他应付款等。
- 发票处理口径明确：有票、无票、待票、不可税前扣除、后续补票。

项目小规模口径说明：

- 进项发票用于成本凭证和内部核对，不作为增值税抵扣项。
- 成本费用记账金额通常按含税成本处理，除非后续企业身份或税务口径调整为一般纳税人。
- 发票缺失不一定阻止内部应付确认，但应形成 `需处理` 或 `待票` 风险。

目标分录：

```text
有票且可记账：
借：主营业务成本/管理费用/销售费用/对应费用科目
贷：应付账款/其他应付款

待票或无票：
借：对应成本费用科目
贷：应付账款/其他应付款
并标记票据风险或税前扣除风险
```

### 8.3 薪酬社保类

来源：

- 薪酬明细。
- 月度绩效。
- 季度绩效。
- 社保公积金确认。

完整前置：

- 薪酬或社保数据已确认。
- 人员、期间、应发、扣款、公司承担部分、个税等明细完整。
- 科目映射完整。

目标分录：

```text
计提工资/绩效：
借：管理费用/项目成本-工资或绩效
贷：应付职工薪酬

计提社保公积金公司承担：
借：管理费用/项目成本-社保公积金
贷：应付职工薪酬/其他应付款

代扣个人承担和个税：
借：应付职工薪酬
贷：其他应付款/应交税费
```

工资发放、社保缴款、个税缴款属于资金凭证或税费凭证，不在权责凭证中重复确认。

## 9. 发票和税额进入凭证的规则

### 9.1 发票台账职责

发票台账承载从税务系统导入或人工补录的票据事实：

- 发票方向：销项、进项。
- 发票颜色：蓝票、红票。
- 发票类型：普通发票、专用发票。
- 发票状态：正常、红冲、作废。
- 开票日期。
- 不含税金额。
- 税额。
- 价税合计。
- 税率或征收率。
- 原蓝票关系。

发票台账不直接做会计记账。它向凭证生成中心提供票税事实。

### 9.2 发票匹配职责

发票匹配负责建立关系：

```text
发票 -> 应收应付
发票 -> 业务确认单据
发票 -> 未开票收入处理
红票 -> 原蓝票
```

当前硬切口径下，普通蓝票不再直接匹配普通收支流水。发票先关联应收应付或其他业务确认事实，再参与权责凭证的收入、成本、费用和税额拆分。收支流水继续服务资金凭证；只有 `后续开票待处理` 这类用于关闭前期未开票收入的场景，才会引用历史资金流水作为申报处理依据。

发票匹配结果用于判断：

- 权责凭证是否可生成完整税额分录。
- 是否存在已收款未开票。
- 是否存在已开票未收款。
- 是否存在红票未关联原蓝票。
- 是否存在后续开票重复确认风险。

### 9.3 发票与凭证的关系

| 场景 | 凭证处理 |
|---|---|
| 已确认收入且已开票 | 权责凭证使用发票不含税金额和税额 |
| 已确认收入但未开票 | 结合申报准备确认是否按未开票收入处理 |
| 已开票但业务未确认 | 不直接生成权责凭证，进入待处理 |
| 红字发票 | 生成冲减或调整凭证，必须关联原蓝票 |
| 进项发票 | 小规模口径下进入成本凭证依据，不作为进项抵扣 |

## 10. 资金凭证和银行对账规则

### 10.1 收支流水职责

收支流水承载系统侧收付款事实：

- 收入或支出方向。
- 发生日期。
- 财务类目。
- 往来对象。
- 金额。
- 对公账户。
- 来源单据。
- 凭证文件。
- 复核状态。

流水复核通过后，说明系统侧认可这笔资金记录。

### 10.2 银行对账职责

银行对账承载银行侧真实发生事实：

- 银行流水导入。
- 银行流水与系统流水匹配。
- 金额、方向、日期、对方户名、摘要核对。
- 对账确认。
- 异常处理、补登记系统流水、补差、冲正。

银行对账不直接替代业务单据，也不直接修改已记账凭证。

### 10.3 资金凭证生成前置

当前执行口径：

```text
系统流水已复核
来源单据和原始凭证完整
会计科目完整
金额与收付款方向有效
```

满足后生成资金凭证：

```text
收款：
借：银行存款
贷：应收账款/其他应收款/收入类科目

付款：
借：应付账款/其他应付款/应付职工薪酬/应交税费
贷：银行存款
```

银行对账不替代上述收付款事实。它在月末用于核对系统流水与银行侧事实：

```text
已复核流水 -> 资金凭证待记账
已复核现金流水 + 银行未对账 -> 可以记账，但不能完成当期结账
银行金额异常或已对账缺少银行关联依据 -> 资金凭证需处理
```

## 11. 调整和冲销规则

### 11.1 调整凭证

调整凭证用于：

- 银行对账发现金额差异后的补差。
- 科目重分类。
- 后续票据或税务处理导致的金额调整。
- 跨期差异调整。

调整凭证必须有：

- 原凭证或原流水。
- 调整原因。
- 调整金额。
- 调整方向。
- 操作记录。

### 11.2 冲销凭证

已记账凭证不能直接编辑。发现错误时：

```text
原凭证 已记账
  ↓
生成冲销凭证
  ↓
原凭证状态 已冲销
  ↓
必要时重新生成正确凭证
```

冲销凭证必须保持与原凭证的强关联。

## 12. 凭证问题原因

完整版本的 `issueReasons` 应采用结构化编码，不只存展示文案。

| 问题编码 | 展示文案 | 适用凭证 | 处理位置 |
|---|---|---|---|
| `missing_source_document` | 来源单据不完整 | 全部 | 来源业务模块 |
| `missing_original_evidence` | 缺少原始凭证 | 全部 | 应收应付、流水、报销、发票 |

| `amount_invalid` | 金额异常 | 全部 | 来源业务模块 |
| `unbalanced_entries` | 借贷不平 | 全部 | 凭证生成规则 |
| `tax_basis_pending` | 税额依据待确认 | 权责凭证 | 应收应付、发票台账关联 |
| `tax_amount_missing` | 缺少税额 | 权责凭证、税费凭证 | 发票台账、税务办理 |
| `bank_reconciliation_source_missing` | 缺少银行对账依据 | 资金凭证、调整凭证 | 银行对账 |

| `reversal_required` | 需要冲销原凭证 | 调整/冲销 | 会计凭证 |

- `FinanceManagementState` 已持有共享 `taxMatterRows`，`税务办理` 和 `会计凭证` 不再各自读取独立税费事项状态。
- `buildAccountingVouchers` 已接收 `FinanceTaxMatterRecord[]`，并为已确认且有应缴金额的税费事项生成 `税费凭证`。
- 已确认但申报事实或申报回执未就绪的税费事项进入 `待生成`，并暴露 `tax_matter_pending`；`processStatus` 仅表示下一办理动作，不再作为会计状态。
- 申报结果已登记但缺少 `申报回执` 的税费事项进入 `需处理`，并暴露 `tax_receipt_missing`；缴款或退税回单由对应资金流水承接。
- 零申报或无需缴纳事项不生成金额凭证。
- 关联税费缴款流水仍由 `收支流水` 生成 `资金凭证`，不在税费凭证中重复确认付款事实。
- 本阶段仍不做正式过账、凭证编号持久化、期间锁定和总账写入；这些留在 Phase 5。

### Phase 5: 制单、记账、冲销、总账

目标：

- `待记账` 候选支持制单。
- `已制单` 凭证支持批量记账。
- 已记账凭证进入总账和报表。
- 已记账凭证只能冲销或调整。
- 增加期间关闭和月结边界。

验收：

- 已记账凭证不可编辑。
- 已制单但未记账凭证不进入总账。
- 冲销凭证与原凭证强关联。
- 关闭期间不允许新增或修改当期记账结果。
- 三张表只消费已记账凭证。

落地状态（2026-06-27）：

- 前端已增加会计凭证生命周期覆盖层：生成候选行可在前端会话内模拟 `已记账`，并通过冲销确认抽屉模拟 `已冲销`。
- 前端记账模拟会分配 mock 正式凭证号，并根据凭证分录派生 `记账影响`；冲销必须填写冲销日期和冲销原因，确认后生成强关联的反向 `冲销凭证`，原凭证历史分录保留并由反向凭证抵消。
- 前端模型已具备期间锁定判断函数；当前没有真实期间关闭 UI、后端锁表或月结操作。
- 已扩展后端契约 `docs/data/finance-accounting-voucher-ledger-contract.md`，定义候选凭证、来源快照、发票引用、持久化凭证、凭证号序列、记账、批量记账、冲销、期间锁定、期间关闭检查、总账明细、科目余额和幂等边界。
- 本阶段没有实现真实数据库迁移、后端 API、正式凭证归档、真实总账写入或三张表生成。

## 16. 模块边界

### 应收应付

负责：

- 权责对象确认。
- 原始业务依据。
- 往来金额和到期日。

不负责：

- 最终会计记账。
- 银行对账。
- 发票税额最终判断。

控制边界（2026-07-10 前端模型落实）：

- `已记账` 或 `已冲销` 的权责凭证一旦关联原事项，原应收应付不得再直接编辑确认金额、类目、期间或到期日；更正只能通过凭证冲销、红字/补差或后续期间调整完成。
- `已结清金额`、`未结清金额`和`收付状态`均由关联收付款流水的**已入账净额**推导：同方向收付款增加结清额，已入账冲正或补差按反方向抵减结清额。不得以单向累计字段作为最终事实。
- `待复核`收付款仅占用可登记额度，不改变结清金额；`退回修改`、`已作废`不占用额度；一条已结清事项发生已入账冲正后必须自动回到`未结清`或`部分结清`。

### 期间结账顺序修复

- 账套启用后必须按自然月连续结账。历史跳月锁不会被静默覆盖，而是标记为`锁定顺序异常`。
- 当前前端 mock 支持对该异常发起`反结账修复`：必须填写原因，原结账快照保留，锁记录改为`已反结账`并记录修复人、修复时间和修复原因。
- 反结账后，期间恢复为开放状态，但仍必须先补齐其直接前序期间结账后才能重新结账。正常业务更正仍优先走后续期间调整；真实环境的反结账须由服务端权限、审批、审计事件和并发事务控制。

### 发票台账/共享发票关联

负责：

- 票据事实。
- 税额。
- 红票原票关系。
- 发票和业务/流水关系。

不负责：

- 直接写会计凭证。
- 替代收款付款确认。

### 收支流水/流水复核

负责：

- 系统侧资金记录。
- 凭证文件。
- 复核。

不负责：

- 银行真实性最终确认。
- 发票税额拆分。

### 银行对账

负责：

- 银行侧事实。
- 银行流水和系统流水匹配。
- 对账差异处理。

不负责：

- 直接修改业务单据。
- 直接改已记账凭证。

### 会计凭证

负责：

- 多来源事实归集。
- 凭证状态判断。
- 分录生成。
- 问题原因提示。
- 记账、冲销和后续总账边界。

不负责：

- 重新编辑业务事实。
- 重新编辑发票事实。
- 重新编辑银行流水事实。

## 17. 测试和验收门禁

必须补充单元测试：

- 已确认应收 + 已匹配销项发票 -> 待记账权责凭证。
- 已确认应收 + 部分开票或未开票 + 来源税额依据完整 -> 待记账权责凭证。
- 已确认应收 + 来源税额依据缺失 -> 停留在来源就绪流，不进入权责凭证候选。
- 红字发票缺少原蓝票关联 -> 需处理。
- 小规模进项发票 -> 成本费用凭证，不生成进项抵扣。
- 已复核流水 + 原始凭证完整 -> 待记账资金凭证。
- 已复核现金流水 + 未银行对账 -> 不能期间结账。
- 银行差异 -> 调整凭证待生成或需处理。
- 已记账凭证 -> 不允许直接修改，只能冲销。
- 科目缺失 -> 停留来源就绪流或进入真实问题状态，不允许 fallback 到管理费用。
- 借贷不平 -> 需处理。

必须补充页面/契约验证：

- 主页面指标显示 `待生成 / 需处理 / 待记账 / 已制单 / 已记账 / 已冲销`。
- 抽屉按凭证类型展示不同依据。
- 问题原因只显示真实阻断，不显示泛化提示。
- 当前 `docs/data/frontend-cross-module-contracts.md` 和 `docs/web/route-page-inventory.md` 同步更新。

## 18. 需要确认的决策

| 决策 | 建议 |
|---|---|
| 资金凭证是否必须银行对账后才能 `待记账` | 当前确认：不必；银行对账作为期间结账前的独立阻断检查 |
| 小规模进项发票是否生成进项税额分录 | 不生成抵扣分录，税额进入成本或费用依据 |
| `待记账` 是否允许批量制单、`已制单` 是否允许批量记账 | 可以，但需要操作记录和后续总账边界 |
| 是否立即做总账和月结 | 不建议同轮做；凭证状态先预留 `已记账` |
| 红字发票是否直接生成冲销凭证 | 必须先关联原蓝票或原凭证，再生成冲销或调整 |
| 是否保留手工凭证入口 | 暂不建议，先做来源驱动；后续可增加受控手工调整凭证 |
