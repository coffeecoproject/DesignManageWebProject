# 社保公积金政策前端硬切与验收 V1

## 范围

本轮仅治理前端政策版本、所属期解析及其与月度缴费计算的契约，不修改真实费率，不增加审批流，不接入后端。

## 领域不变量

1. 政策版本只持久化 `草稿` 或 `已发布`；`待生效`、`当前生效`、`历史`由当前月份派生。
2. 同一配置类型、同一生效月份只能存在一个版本，包括草稿。
3. 已发布版本不可删除、不可重复发布、不可原地修改。
4. 新版本只能从草稿发布，且生效月份必须晚于该类型最近已发布版本。
5. 发布未来月份版本不会改变当前月份政策；到其生效月份后，所属期解析自动切换。
6. 社保和公积金分别维护版本，月度缴费记录冻结实际使用的 `policyVersionId`。
7. 工资扣减继续消费月度核定结果，不直接读取配置页的当前展示版本。

## 验收矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| SI-POL-01 | 2026-06 查看 V0、V1、V2 草稿 | V0 为历史，V1 当前生效，V2 草稿 |
| SI-POL-02 | 发布 2026-07 V2 | V2 待生效，2026-06 仍使用 V1 |
| SI-POL-03 | 计算 2026-07 缴费 | 使用 V2，并冻结 V2 的版本标识 |
| SI-POL-04 | 新增同类型同生效月份版本 | 阻断保存 |
| SI-POL-05 | 发布早于最近已发布月份的草稿 | 阻断发布 |
| SI-POL-06 | 删除或重复发布已发布版本 | 阻断操作 |
| SI-POL-07 | 既有月度核定与工资扣减 | 计算结果保持回归通过 |
| SI-POL-08 | 统一业务月份从 2026-06 推进至 2026-07 | 已发布 V2 自动由待生效转为当前生效，V1 转为历史 |
| SI-POL-09 | 2026-06 与 2026-07 分别新建同类配置 | 复制来源分别为对应月份的 V1 与 V2，不回退到种子月份 |

## 门禁

- `document_gate`: 本文档与领域不变量存在。
- `automated_gate`: 生命周期模型测试、社保缴费模型测试、Web typecheck、lint、build、AI Native check。
- `evidence_gate`: 每个验收场景必须有自动测试或现有跨模块回归证据。
- `manual_approval_gate`: 无；本轮不触及生产、真实政策数值、后端或数据迁移。

期间解析必须显式接收所属期。配置页面和状态 Provider 使用项目统一的 `frontendBusinessToday` 推导当前月份；种子月份只允许用于构造静态 Mock，不得作为业务解析器的默认参数。

## 后端接入边界

后端接入时应延续相同编码和约束，并用数据库唯一约束保证同类型、生效月份唯一。已发布版本应只读，缴费记录必须保存实际使用的政策版本快照或版本标识。
