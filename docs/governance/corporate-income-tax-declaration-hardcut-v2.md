# 企业所得税申报准备硬切 v2

## 目标

面向小规模纳税人中采用查账征收的小型微利企业，在同一个“申报准备”子模块中明确分离企业所得税季度预缴与年度汇算清缴，不再把年度汇算当成第四季度预缴的延伸。

## 申报场景

- `季度预缴`：按本年累计利润和已预缴税额计算本季应预缴金额。
- `年度汇算`：使用全年已记账数据，完成年度纳税调整，抵减全年已预缴税额，得出应补或多缴结果。

税务办理必须通过 `税种 + 期间 + 申报场景` 承接申报准备，不得仅通过税种和期间模糊匹配。

## 季度预缴

季度预缴继续执行 v1 的本年累计口径：

```text
本年累计利润总额
+ 累计纳税调增
- 累计纳税调减
- 弥补以前年度亏损
= 累计实际利润额

累计应纳所得税额 - 本年已预缴 = 本季应预缴
```

季度账务来源必须覆盖年初至申报季末，不能只检查本季度三个月。以前季度只有取得“申报成功”或“零申报”的正式结果才视为申报连续，“无申报义务”不替代企业所得税季度申报结果。

季度预缴中的累计纳税调整、以前年度亏损弥补和抵免所得税额属于税务事实，不得从固定 Mock 或展示文案继承：

- 纳税调整必须保留事项、账载金额、税收金额、方向、调整金额、来源模块和来源单号。
- 以前年度亏损弥补金额大于零时必须保留亏损台账来源单号。
- 抵免所得税额大于零时必须保留抵免资料来源单号。
- 三类事实即使本期为零，也必须显式完成核对后才能确认申报准备。
- 国家限制和禁止行业判定由带生效期的只读税务口径提供，不在每个季度重复手工确认。

## 年度汇算

年度汇算只在以下条件成立后允许确认：

1. 12 月会计期间已结账。
2. 年度财务报表可出具。
3. 第四季度企业所得税预缴已完成。
4. 年度纳税调整明细已归集并确认。
5. 以前年度可弥补亏损已核对；存在弥补金额时必须保留来源单号。
6. 年度汇算口径已确认。

系统不得固定生成业务招待费、税收滞纳金或以前年度亏损。每条年度调整必须来自已核对的年度税务资料，并保留账载金额、税收金额、调整方向、调整金额、来源模块和来源单号。无调整事项时，也必须显式完成年度纳税调整核对。

年度申报表范围按实际业务事实确定：

- `A000000` 与 `A100000` 为年度汇算基础表及主表。
- 存在会计与税收差异时承接 `A105000`。
- 存在职工薪酬时承接 `A105050`。
- 存在固定资产折旧、无形资产或长期待摊费用摊销时承接 `A105080`。
- 存在以前年度亏损弥补时承接 `A106000`。

页面当前呈现年度来源、调整事实、亏损弥补和汇算结果，不伪造电子税务局表单或回执。申报表生成与后端持久化仍属于后续契约范围。

## 页面边界

- 申报准备列表显式展示“申报类型”。
- 季度页面展示累计预缴口径。
- 季度税务资料通过独立核对抽屉维护；未核对时阻断最终确认。
- 年度页面展示全年结果、年度前置条件和纳税调整明细。
- 年度税务资料通过独立核对抽屉维护；未核对时阻断最终确认。
- 税务办理只消费已确认结果；准备未完成时应纳金额为零且不可申报。

## 当前证据边界

当前是前端会话内模型；已实现业务状态、来源快照和页面阻断，但不得宣称为法定申报、电子税务局回执或后端持久化证据。

自动验收映射见 `docs/testing/corporate-income-tax-frontend-acceptance-traceability.md`；验收编号未被实际执行并通过时，不得声明企业所得税前端链路完成。

## 申报后办理链路

- 电子税务局申报成功后，系统登记官方申报结果、回执和本版应补或应退金额。
- 本版应补可分次登记缴款，但累计不得超过本版待缴金额。
- 本版应退必须先登记退税申请及外部回执，再根据税务机关处理结果分次登记到账；这不是平台内部审批。
- 未缴款时可更正或作废；已存在缴款、退税申请或退税到账事实时只能更正。
- 更正保留原申报版本和累计缴退税事实；新版本只处理本次更正产生的应补或应退差额，会计端只生成版本间差额凭证。
- 企业所得税季度预缴只允许调整最近一期；年度汇算申报后，不再调整该年度季度预缴记录。
