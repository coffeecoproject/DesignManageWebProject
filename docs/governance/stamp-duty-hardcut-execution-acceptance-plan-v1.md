# 印花税业务链路硬切执行与验收方案 v1

## 1. 文档目的

本方案用于把当前前端中的印花税静态事项，硬切为可追溯、可测算、可确认、可办理、可记账的真实业务链路。

本轮目标链路：

```text
已书立的应税凭证 / 营业账簿年度新增额
  -> 印花税税源识别
  -> 申报准备
  -> 税务办理
  -> 权责凭证
  -> 税费缴款流水
  -> 资金凭证
  -> 总账 / 期间结账 / 财务报表
```

印花税不通过应收应付生成。合同是否收款、付款、开票或结清，不决定印花税纳税义务是否发生。

## 2. 范围与证据边界

### 2.1 本轮范围

- 客户合同补齐印花税识别所需的业务事实。
- 新建独立的印花税领域模型和税源记录。
- 申报准备增加印花税场景、税源明细、计算结果和确认快照。
- 税务办理只承接已确认的印花税申报准备，不允许再次手工录入应纳金额。
- 补齐合同类、无固定金额凭证、补充协议、营业账簿的计算规则。
- 复用现有税费权责凭证、缴款流水、资金凭证和总账链路。
- 重构 Mock 数据和前端测试，使页面可完整演示正向与异常流程。

### 2.2 不在本轮范围

- 不新建采购合同、供应商合同或租赁合同主模块。
- 不接入电子税务局，不执行真实申报和缴款。
- 不新增后端数据库、API 或迁移。
- 不允许业务人员配置法定税目、税率和政策版本。
- 不以合同名称关键词作为最终税务分类依据。
- 不把应收应付、发票或收付款状态作为印花税发生条件。

### 2.3 当前证据边界

本轮仍为前端会话内模型。页面状态、操作记录和 Mock 回执仅用于验证产品流程，不构成正式纳税申报、缴税、会计档案或后端持久化证据。

## 3. 真实业务口径

### 3.1 纳税义务与计税依据

- 印花税税源来自《印花税法》税目税率表列明的合同、产权转移书据和营业账簿，不是所有合同都征税。
- 应税合同和产权转移书据以凭证所列金额为计税依据；单独列明的增值税税款不计入计税依据。
- 仅列明税率、未单独列明增值税税额时，按凭证所列全额计算。
- 未列明金额的应税凭证，应在书立后的首个纳税申报期申报凭证书立情况；实际结算金额确定后，在下一个纳税申报期按实际结算金额申报缴税。
- 同一凭证包含多个税目且分别列明金额时分项计算；未分别列明时标记为待确认，不由系统擅自拆分。
- 已缴纳印花税的营业账簿，后续只对实收资本与资本公积合计金额的新增部分计税，不得每年按全部余额重复计税。

### 3.2 小规模企业减免

当前项目主体为湖北武汉小规模纳税人。2023-01-01 至 2027-12-31，符合条件的增值税小规模纳税人、小型微利企业和个体工商户，印花税（不含证券交易印花税）按政策减半征收。

系统必须依所属期命中政策版本和资格快照，计算顺序为：

```text
计税依据 × 税目税率 = 减免前税额
减免前税额 - 其他法定减免 = 减免基数
减免基数 × 六税两费减征比例 = 减征额
减免前税额 - 其他法定减免 - 减征额 = 预计应纳税额
```

不得把 50% 直接写死在页面，也不得在政策有效期外继续沿用。

### 3.3 申报周期

- 合同和产权转移书据的按季或按次口径，以主管税务机关的税种认定为准。
- 营业账簿按年或按次申报；同一纳税年度内不得随意切换。
- 项目当前无法从代码证明湖北武汉主体的实际税种认定，因此政策模型必须保存主体级申报周期配置，Mock 首版采用：合同类 `按季`、营业账簿 `按年`。
- 页面不得同时出现 `2026-Q2` 与 `按次申报` 这种互相冲突的期间口径。
- 按季或按年计征的，自季度或年度终了之日起十五日内申报缴纳；按次计征的，自纳税义务发生之日起十五日内申报缴纳。

### 3.4 官方依据

- [中华人民共和国印花税法](https://fgk.chinatax.gov.cn/zcfgk/c100009/c5193058/content.html)
- [印花税计税依据问答](https://www.chinatax.gov.cn/chinatax/n810356/n3010387/c5196049/content.html)
- [印花税若干事项政策执行口径](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5202012/content.html)

## 4. 当前代码审查结论

### 4.1 客户合同

当前 `CustomerContractRecord` 只有合同类型、金额模式、金额、签署日和文件，无法可靠回答：

- 凭证是否属于法定印花税税目；
- 金额是否含税、是否单独列明增值税；
- 补充协议是新增金额还是仅修改非金额条款；
- 无固定金额合同何时形成实际结算金额；
- 同一签署版本是否已形成税源；
- 对方书立人的纳税人识别号和涉及金额。

现有合同保存要求签署日期和签署文件，因此当前已保存记录可视为“已书立凭证”，但仍需增加签署版本和税务事实快照，避免编辑覆盖历史。当前客户档案也没有纳税人识别号，必须补为客户主数据，并由合同税源读取；不得把客户名称当作完整的税务身份。

### 4.2 非客户合同来源

当前没有供应商合同、采购合同或租赁合同主数据模块。外协结算、材料采购和运营费用不能替代已签署的应税合同事实。

本轮应在印花税申报准备中提供“补录应税凭证”，用于录入真实存在但系统尚无主模块承接的签署凭证。补录必须逐份记录凭证，不允许只输入汇总税额。

### 4.3 申报准备

现有类型虽然包含 `印花税`，但没有印花税申报场景、税源明细、汇总结果和确认逻辑；数据更新函数对印花税直接跳过。

### 4.4 税务办理

现有静态 Mock 使用 `2026-Q2 + 按次`，并引用不存在的“特定业务事项 / 经营数据”。印花税也未被纳入申报准备驱动税种，税务办理表单仍可直接写应纳金额。

上述内容必须删除，不保留兼容分支。

### 4.5 会计凭证及后续链路

现有科目和分录已具备承接能力：

```text
确认印花税：借 5403 税金及附加
            贷 2221.05 应交税费-应交印花税

实际缴款：  借 2221.05 应交税费-应交印花税
            贷 1002 银行存款
```

税费事项生成权责凭证、缴款回单生成流水和资金凭证的现有链路可以复用。本轮不新建应付记录，也不修改上述会计科目。

## 5. 目标领域模型

### 5.1 合同业务事实

`CustomerContractRecord` 增加以下业务字段，不在合同页面展示税率或税额：

```ts
type ContractStampDutyFacts = {
  businessNature: ContractBusinessNature;
  amountTaxMode: '价税分列' | '含税未分列' | '不涉及增值税';
  vatAmount?: number;
  signedVersionNo: string;
  parentContractId?: string;
  agreementChangeType?: '新增金额' | '减少金额' | '仅变更非金额条款';
  agreementChangeAmount?: number;
};
```

`businessNature` 使用有限业务选项，而非税目名称：

- 设计及咨询服务
- 工程施工
- 采购或销售
- 租赁
- 技术服务
- 借款
- 产权转移
- 其他

系统只对确定性业务性质自动分类。`设计及咨询服务` 等无法仅凭名称判断是否属于承揽合同的，进入 `待确认`，不自动判税。

### 5.2 印花税政策模型

将 `FinanceStampDutyPolicy` 从展示文本硬切为结构化模型：

```ts
type FinanceStampDutyPolicy = {
  declarationCycles: {
    taxableDocuments: '按季' | '按次';
    capitalBooks: '按年' | '按次';
  };
  items: FinanceStampDutyTaxItemPolicy[];
  microTaxFeeReductionRate: number;
  reductionEligibility: '符合' | '不符合' | '待确认';
  effectiveFrom: string;
  effectiveTo: string;
};
```

税目表必须覆盖项目可能使用的法定税目，并保存法定税率、适用凭证范围和政策来源。业务层只读。

首版结构化税目表至少完整包含：

| 税目 | 法定税率 |
| --- | ---: |
| 借款合同、融资租赁合同 | 0.005% |
| 买卖合同、承揽合同、建设工程合同、运输合同、技术合同 | 0.03% |
| 租赁合同、保管合同、仓储合同、财产保险合同 | 0.1% |
| 土地使用权出让书据、土地使用权及房屋等建筑物和构筑物所有权转让书据、股权转让书据 | 0.05% |
| 商标专用权、著作权、专利权、专有技术使用权转让书据 | 0.03% |
| 营业账簿 | 0.025% |

一般咨询服务合同不因名称中包含“服务”自动纳税；建设工程设计、技术服务或承揽成果等必须结合实际权利义务确认对应税目。

### 5.3 税源记录

新建 `financeStampDutyModel.ts`，定义独立税源记录：

```ts
type FinanceStampDutySourceRecord = {
  id: string;
  sourceType: '客户合同' | '补录应税凭证' | '营业账簿';
  sourceId: string;
  sourceVersion: string;
  sourceNo: string;
  documentNo?: string;
  documentName: string;
  counterparty: string;
  counterpartyTaxId?: string;
  counterpartyInvolvedAmount?: number;
  signedAt?: string;
  obligationPeriod: string;
  declarationScenario: '季度申报' | '按次申报' | '年度申报';
  taxItem: FinanceStampDutyTaxItem | '待确认';
  amountTaxMode: FinanceStampDutyAmountTaxMode;
  statedAmount?: number;
  statedVatAmount?: number;
  settlementAmount?: number;
  settlementDate?: string;
  taxableBasis?: number;
  legalTaxRate?: number;
  taxBeforeReduction?: number;
  reductionPolicyCode?: string;
  reductionPolicyName?: string;
  reductionAmount?: number;
  estimatedPayableAmount?: number;
  resolutionStatus: '待确认' | '可申报' | '待后续结算' | '已完成';
  evidenceFiles: RelatedFileRecord[];
  snapshotKey: string;
};
```

关键约束：

- `sourceId + sourceVersion + taxItem` 唯一，防止重复生成税源。
- `sourceNo` 是系统来源单号；`documentNo` 是应税凭证自身编号，凭证没有编号时允许为空，两者不得混用。
- 客户合同税源从客户主数据读取对方纳税人识别号；补录凭证由操作人录入并校验。营业账簿不要求对方书立人信息。
- 每次申报准备保存不可变期间快照；上游后续修改不得覆盖历史快照。
- 补充协议按新增或减少金额形成独立差额税源，不重算原合同全额。
- 已申报后计税依据增加，生成补税差额税源；减少时进入更正处理，不自动生成负数税额或覆盖原税额。
- 无固定金额凭证在首个申报期以 `待后续结算` 申报书立事实，当前计税金额为 0，但不阻断该期确认。
- 后续每次实际结算形成独立结算事件，在结算后的下一个申报期按本次实际结算金额进入申报准备；不得覆盖首次书立记录，也不得重复累计已申报结算金额。

### 5.4 营业账簿税源

营业账簿税源读取已记账总账与期初余额中的 `3001 实收资本`、`3002 资本公积`：

```text
本年期末实收资本与资本公积合计
- 历史已缴印花税对应的最高计税基数
= 本年新增计税依据（最低为 0）
```

首年历史已缴基数必须作为账套初始化或税源补录事实保存。缺少历史已缴基数时，状态为 `待确认`，不得按当前全部余额自动生成应纳税额。

## 6. 状态机与不可变规则

### 6.1 税源状态

```text
待确认 ----确认税目/业务事实----> 可申报
可申报 ----确认本期申报准备----> 已完成
可申报 ----无固定金额凭证首期确认----> 待后续结算
待后续结算 ----发生实际结算----> 生成下一申报期结算事件
下一期结算事件 ----确认申报准备----> 已完成或继续待后续结算
```

### 6.2 申报准备状态

沿用页面层状态：

- `准备中`：存在待确认税目、缺原始凭证、政策版本缺失或减免资格待确认。无固定金额凭证已完整登记书立事实时，不因尚未结算而阻断首期申报。
- `可申报`：税源均已确认、汇总平衡且政策版本有效。
- `已进入税务办理`：已生成或更新对应税务事项，原准备结果只读。

### 6.3 税务办理状态

印花税进入与增值税、企业所得税一致的申报准备驱动流程：

- 准备未完成：税务办理不可申报，应纳金额为 0。
- 准备已确认：税务办理读取确认快照和应纳金额。
- 税务办理只允许打开官方入口、归档正式申报表、申报结果回执和缴款回单，并回填外部结果。
- 税务办理不允许编辑税目、计税依据、税率、减免或应纳金额。

## 7. 页面重构

### 7.1 合同管理

新增和编辑抽屉增加：

- 业务性质；
- 价税方式；
- 单独列明的增值税金额（仅价税分列时显示）；
- 签署版本；
- 补充协议关联原合同、变更类型和变更金额。

客户档案增加纳税人识别号，合同选择客户后只读引用，不在每份合同重复维护。

合同详情只展示业务事实，不展示“印花税税目、税率、预计税额”。税务结果只在税务模块查看。

### 7.2 申报准备

印花税抽屉使用现有 `DetailDrawerShell + DetailTabs`，只保留三个 Tab：

1. `准备结果`：期间、申报场景、计税依据、减免前税额、减征额、预计应纳税额、状态。
2. `税源明细`：逐份凭证或营业账簿增量，展示来源、税目、计税依据、税率、减免、预计税额、处理状态。
3. `操作记录`：确认、补录、重新测算和进入税务办理的留痕。

页面主操作：

- `补录应税凭证`：只用于系统当前没有主数据模块的真实签署凭证。
- `确认申报数据`：仅在所有阻断项清零后启用。

不增加人员、对象、税率等冗余筛选。沿用税种、申报场景、期间和关键字的既有克制筛选结构。

### 7.3 税务办理

- 删除静态 `TAX-2026Q2-STAMP` Mock 和“特定业务事项 / 经营数据”。
- 删除印花税手工新建、编辑应纳金额的能力。
- 印花税只显示申报准备已确认的来源摘要。
- 回执与缴款文件继续使用现有可预览、可下载文件组件。

### 7.4 系统管理 / 税务口径

- 展示印花税政策版本、生效期、主体申报周期、法定税目税率和六税两费资格。
- 全部只读，不提供业务侧编辑。
- 去掉“按次 / 按期”模糊文本，显示实际配置，例如“应税合同：按季；营业账簿：按年”。

## 8. Mock 数据重构

Mock 必须覆盖以下真实场景：

1. 工程施工合同：固定金额、价税分列、可自动确定税目。
2. 设计咨询合同：业务边界不明确，进入待确认，不自动套用承揽税率。
3. 无固定金额框架合同：首个申报期申报书立事实，并在后续结算期形成独立结算事件。
4. 补充协议：增加金额，仅对增加部分形成税源。
5. 采购或租赁凭证：通过“补录应税凭证”进入，不伪造供应商合同模块。
6. 营业账簿：本年实收资本或资本公积新增，只对新增额计税。
7. 已确认并进入税务办理：准备快照锁定，可上传申报与缴款回执。
8. 六税两费减半：同时展示减免前税额、减征额和预计应纳税额。

Mock 中不得出现：

- 期间与申报场景冲突；
- 已关联但缺少来源记录；
- 已确认但税目、计税依据或政策版本为空；
- 从应收应付、发票或收付款自动生成印花税义务；
- 仅为演示而存在的“特定业务事项”“经营数据”等虚假来源。

## 9. 硬切执行顺序

### 阶段 A：领域与政策

1. 新建 `financeStampDutyModel.ts` 及单元测试。

## 11. 验收标准

### 11.1 领域单元测试

- 只有法定应税凭证进入税源池，普通咨询等不确定场景进入待确认。
- 客户合同可以追溯客户纳税人识别号；补录凭证缺少必要对方信息时不可确认。
- 价税分列时扣除单独列明增值税；未分列时按凭证全额。
- 无固定金额凭证首期可按书立事实确认，计税金额为 0，并保持待后续结算。
- 实际结算发生后只在下一个申报期计算本次结算金额，且不能重复申报同一结算事件。
- 补充协议只计算差额，不重复计算原合同。
- 相同来源版本不能重复生成税源。
- 六税两费减免按所属期政策版本和资格快照计算。
- 营业账簿只计算实收资本与资本公积新增额。
- 历史已缴基数缺失时阻断，不按全部余额猜测。
- 已确认快照不被上游编辑静默覆盖。

### 11.2 跨模块集成测试

- 已签署客户合同形成对应期间税源；合同收款和开票状态不影响税源发生。
- 补录应税凭证可进入同一申报准备，不生成虚假供应商合同。
- 印花税准备未完成时，税务办理保持阻断且应纳金额为 0。
- 确认申报准备后，税务办理金额与准备快照一致。
- 确认税务事项后生成借 `5403`、贷 `2221.05` 的权责凭证。
- 上传缴款回单并登记缴款后，生成借 `2221.05`、贷 `1002` 的资金凭证。
- 整条链路不创建应收应付记录。
- 已记账或已锁期来源只能通过差额更正，不可覆盖原快照。

### 11.3 页面验收

- 合同抽屉字段随价税方式和补充协议类型正确显隐。
- 申报准备印花税抽屉仅有“准备结果 / 税源明细 / 操作记录”三个 Tab。
- 补录表单只录业务凭证事实，不允许直接录税率和应纳税额。
- 税务办理不存在印花税新增入口和金额编辑入口。
- 税务口径清楚展示合同类与营业账簿的实际周期，不再展示模糊“按次 / 按期”。
- 文件统一使用可预览、可下载组件。
- 页面无穿透组件、无重复说明文案、无横向溢出、无按钮状态漂移。

## 12. 门禁分类

| 门禁 | 类型 | 当前状态 | 阻断效果 |
| --- | --- | --- | --- |
| 现行税法与政策版本 | document_gate | 已核对官方来源 | 未命中版本不得测算 |
| 税源事实完整性 | evidence_gate + automated_gate | 前端模型和单测已实现 | 不完整不得确认申报准备 |
| 已确认快照不可变 | document_gate + automated_gate | 前端会话态已实现 | 禁止静默覆盖 |
| 税务办理来源一致性 | automated_gate | 前端会话态已实现和测试 | 无确认准备不得办理 |
| 会计分录平衡 | automated_gate | 已纳入前端会计回归 | 不平不得记账 |
| 期间锁定 | automated_gate | 按税源纳税义务期间守卫 | 锁期不得改原来源 |
| 真实申报与缴款 | manual_approval_gate + evidence_gate | 本轮不执行 | 不得宣称已申报或已缴税 |

## 13. 完成定义

同时满足以下条件才可关闭本轮任务：

1. 旧静态印花税事项、虚假来源和手工金额入口已完全删除。
2. 合同、补录凭证、营业账簿三类税源可进入同一申报准备。
3. 税目、计税依据、减免和申报周期均由所属期政策与业务事实推导。
4. 申报准备确认后能完整进入税务办理、权责凭证、缴款流水、资金凭证和总账。
5. Mock 数据覆盖正向、待确认、待后续结算、差额调整和营业账簿场景。
6. 单元、集成、构建、AI Native 和浏览器验收全部通过。
7. 跨模块契约、测试计划和治理证据已同步。

## 14. 后端接入前保留事项

- 税源记录、政策版本、确认快照和外部办理结果的持久化契约。
- 合同签署版本、补充协议关系和证据文件对象的 API 契约。
- 主管税务机关税种认定和实际申报周期的主体配置来源。
- 电子税务局申报结果与系统测算不一致时的差异说明和回执留档。
- 已申报后补税、退税或抵缴的正式更正状态机。

这些事项不阻止本轮前端完整展示真实流程，但未落地前不得声明税务生产闭环。

## 15. 前端实施记录

本轮已按硬切口径落地以下前端能力：

- `financeStampDutyModel.ts` 统一承载合同、补录凭证、无固定金额结算事件和营业账簿税源计算。
- 印花税政策已结构化为实际申报周期、法定税目税率、六税两费资格与减征比例。
- 客户主数据补充纳税人识别号；合同补充业务性质、价税方式、签署版本和补充协议差额事实。
- 申报准备保存税源行、汇总、来源快照和确认快照，并提供逐份“补录应税凭证”。补录只接受法定税目、凭证事实与证据文件，不接受税率或税额。
- 待确认税源支持形成应税、非应税或调减抵缴结论；多税目分配必须覆盖完整计税依据，系统不默认替操作人选择税目。
- 税源详情复用统一抽屉、详情 Tab 和相关文件组件；主申报抽屉继续保持“申报概览 / 申报明细 / 操作记录”职责边界。
- 待后续结算税源可从详情抽屉登记实际结算；结算单号、金额、日期、价税拆分和结算依据形成独立税源，不覆盖原始凭证。
- 后续结算按实际金额确定日归入对应申报所属期；季度末结算仍归当季度，价税分列时必须登记并扣除单列增值税额。
- 营业账簿通过 `financeStampDutyLedgerBridge.ts` 读取总账 `3001 / 3002` 期末余额，并与历史已税最高基数比较；已删除页面固定本期资本金额。
- 税源确认按纳税义务所属期间执行锁期校验，不允许用处理日期绕过历史锁期。
- 税务办理改为申报准备驱动，旧虚假来源与冲突的按次周期已删除。
- 会计回归覆盖印花税权责凭证 `5403 / 2221.05`、更正差额凭证及缴款 `2221.05 / 1002` 资金链路。
- 外部申报结果与准备快照不一致时必须登记差异原因；已缴申报禁止直接作废，只能版本化更正并按净差额进入补缴或退税。

本轮印花税自动化覆盖不猜测税目、价税分离、无固定金额后续结算、多税目分配、非应税结论、调减金额闭合、营业账簿总账桥接、历史已税基数、申报差异、缴退税更正和会计勾稽。可执行映射见 `docs/testing/stamp-duty-frontend-acceptance-traceability.md`，当前共 17 项专项验收。

本记录仅代表前端会话态模型和 Mock 流程，不代表后端持久化、真实申报、真实缴款或生产会计档案已经完成。
