# 前端统一授权模型 v1

## 1. 范围

本轮只建立前端领域契约和交互控制，不涉及后端、数据库、登录态、服务端鉴权或审计持久化。前端授权用于统一菜单、路由、按钮和数据可见范围，不构成安全边界；后端接入后必须使用相同权限编码和范围规则重新鉴权。

## 2. 关系模型

```text
账号 -> 系统角色 -> 系统权限
人员 -> 任职记录 -> 岗位 -> 业务角色默认权限包
                         -> 岗位追加权限
                         -> 岗位固定数据范围
```

- 系统角色固定为 `超级管理员 / 管理员 / 普通人员`，跟随账号，只授予系统管理权限。
- 业务角色是只读默认权限包，不允许在业务页面修改权限定义。
- 人员可以存在多条有生效区间的任职记录，并可同时担任多个岗位。
- 岗位可以绑定多个业务角色、追加业务权限，并配置固定数据范围。
- 系统角色不授予业务权限；CEO 岗位也不会自动把账号提升为管理员。

## 3. 有效授权计算

有效业务权限只聚合以下记录：账号启用、人员关系有效、任职处于生效期、岗位启用。业务角色是固定权限包，不具有独立启停状态。多岗位权限取并集；数据范围按预定义顺序取最宽范围。任职结束、岗位停用、人员关系结束或账号停用后，相应授权立即从前端有效结果中移除。

固定数据范围：

- 人员：`本人 / 全部人员`
- 任务：`本人参与 / 负责验收 / 全部任务`
- 客户：`关联品牌 / 全部客户`
- 财务：`不可访问 / 查看 / 管理`
- 薪酬：`本人 / 全部人员`

## 4. 前端消费边界

- 菜单：由有效授权过滤，不展示无权入口。
- 路由：与菜单共用同一授权结果，直接输入受控路径也会拒绝。
- 重定向：旧路径和父路径继承目标页面权限。
- 按钮：查看权限不等于维护权限；例如人员档案新增、编辑单独检查 `people.archive.manage`。
- 数据：人员总览、人员档案和任务列表使用同一授权结果过滤记录。
- 未登记的受控业务路径默认拒绝；未知非业务路径仍进入 404。

## 5. 验收场景

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| AUTH-01 | 同一人员多岗位 | 权限取并集，范围取最宽 |
| AUTH-02 | 任职结束、岗位停用或人员离职 | 对应业务权限立即回收 |
| AUTH-03 | 超级管理员无岗位 | 仅有系统权限，不自动获得业务权限 |
| AUTH-04 | 路由与记录范围 | 共用同一有效授权结果 |
| AUTH-05 | 账号停用 | 自助页、业务页、系统页全部拒绝 |
| AUTH-06 | 父路径与旧路径重定向 | 继承目标权限；遗漏的受控路径默认拒绝 |

## 6. 后端接入边界

后端接入时必须补齐：账号与人员绑定持久化、任职生效区间、岗位状态、固定业务角色权限包版本、服务端资源鉴权、数据范围查询约束、越权拒绝审计、并发与缓存失效。前端隐藏菜单或按钮不能替代这些控制。
