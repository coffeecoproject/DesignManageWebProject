# 增值税及附加硬切方案 V1

Date: 2026-06-21

Status: ready_for_implementation

Owner: tax-management frontend scope

## 1. 目标

本方案用于硬切 `税务管理` 中增值税及附加的业务口径、页面边界、数据模型和验收门禁。

本轮先形成执行文档，不直接修改前端代码。后续实现时不做兼容旧口径，不保留旧的“票款差异阻断申报”“流水复核阻断申报”“含税金额直接计税”等尾巴。

## 2. 项目固定业务口径

当前公司口径按以下规则落地：

- 地区：湖北省武汉市。
- 纳税人类型：小规模纳税人。
- 增值税及附加申报周期：季度。
- 项目固定优惠口径：季度不含税销售额 300,000 元以下免征增值税。
- 最终法定结果：以湖北省电子税务局申报结果、申报回执、缴款回单为准。
- 系统职责：准备数据、提示待确认事项、记录办理过程，不替代电子税务局最终申报。

注意：

- `季度 300,000 元以下免税` 按本项目湖北武汉主体适用的小规模口径处理，不写成湖北省单独设定的地方政策。
- 免税阈值按“不含税销售额”判断，不按收款含税金额判断。
- 小规模纳税人的进项发票用于成本和凭证管理，不作为增值税抵扣项。
- 增值税及附加的测算只能作为申报准备参考；税务办理回填后的实际结果才进入最终记录。
- 如果当期政策、企业税务登记身份、专票开具限制、减免政策口径与本方案不一致，以电子税务局最终口径为准。

## 3. 核对到的真实规则

已核对规则：

- 增值税是价外税，销售额不包括增值税额。
- 小规模纳税人适用简易计税方法。
- 小规模纳税人标准为年应征增值税销售额未超过 500 万元。
- 简易计税方法下，应纳税额按销售额乘征收率计算。
- 简易计税对应的进项税额不得从销项税额中抵扣。
- 未达到起征点或免征标准的销售额可免征增值税，具体标准由国务院规定。
- 增值税纳税期限可以按月或按季度，按月或按季度申报的，应在期满后 15 日内申报纳税。
- 纳税义务发生时间原则上按收讫销售款、取得索取销售款凭据或先开具发票的日期确认。

外部资料核查记录：

- 财政部小规模纳税人减免增值税公告候选页面在本次核查中返回 502，不能作为已验证证据归档。
- 中国政府网候选政策页在本次核查中返回页面不存在，不能作为已验证证据归档。
- 国家税务总局候选内容页返回总局首页，不能作为具体政策条文证据归档。

待补证据：

| 证据 | 用途 | 当前处理 |
|---|---|---|
| 小规模纳税人季度 300,000 元以下免征增值税的官方公告链接 | 固化项目免税阈值来源 | 实现前补入 evidence 或税务口径配置备注 |
| 湖北省电子税务局申报页截图或回执样例 | 验证系统口径与实际申报入口一致 | 首次真实办理后补入 evidence |
| 当前公司税务登记纳税人身份截图 | 确认是否仍为小规模纳税人 | 上线前补入 evidence |

因此，本方案将“湖北武汉小规模季度 30 万以下免税”写为用户确认的项目固定口径，并要求后续补充官方公告链接或电子税务局截图作为证据。实现层不能把前端配置当成法律来源。

## 4. 当前模块问题

### 4.1 申报准备把内部核对当成申报阻断

当前 `申报准备` 中存在 `票款差异确认` 和 `流水复核影响` 等事项。它们适合做内部风险提示，但不应直接决定是否可以形成增值税申报准备。

调整后：

- 发票与流水是否完全匹配，是内部核对风险。
- 银行流水是否全部复核，是资金事实和账务完整性问题。
- 增值税申报准备的硬阻断，只保留影响申报口径的事项。

### 4.2 增值税测算口径不完整

当前数据中有 `vatPayableAmount = declaredSalesAmount * 1%` 的口径，未显式处理：

- 不含税销售额。
- 季度 300,000 元免税阈值。
- 小规模征收率和阶段性优惠征收率的区别。
- 附加税以实际缴纳的增值税、消费税为基础。
- 电子税务局最终回填覆盖前端测算结果。

### 4.3 发票类型字段不足

当前发票台账缺少足够明确的票据业务字段，导致蓝票、红票、前期未开票后续开票、普通发票和专用发票的申报处理难以区分。

### 4.4 进项发票容易被误解为抵扣

小规模纳税人进项发票不能抵扣增值税。当前页面如果在增值税申报数据中突出进项发票金额，容易让用户误解为“进项抵扣”。

调整后：

- 进项发票仍保留在发票台账。
- 进项发票用于成本凭证和内部核对。
- 增值税及附加申报准备中不把进项金额作为抵扣项呈现。

## 5. 目标流程

```mermaid
flowchart LR
  A["发票台账"] --> B["发票匹配"]
  B --> C["申报准备"]
  C --> D["税务办理"]
  D --> E["回执与实际结果"]
  E --> F["收支流水/税务记录"]
```

### 5.1 发票台账

职责：

- 承载从税务系统导入的发票事实。
- 支持月度视角和申报周期视角。
- 区分销项、进项、蓝票、红票、普通发票、专用发票。
- 对发票匹配状态做结果展示，不在明细表里塞入流水匹配细节。

不承担：

- 不在发票台账里做复杂人工匹配。
- 不在发票台账里确认申报口径。
- 不在发票台账里处理缴税和回执。

### 5.2 发票匹配

职责：

- 处理待办项，不按某一个月静态展示。
- 蓝字销项发票匹配已复核收入流水。
- 红字发票关联原蓝字发票。
- 前期未开票收入后续开票时，关联原已申报未开票流水。
- 已完全匹配、已申报闭环的发票不再进入待匹配池。

不承担：

- 不允许手动修改匹配金额。
- 不允许把金额不一致的流水强行匹配成一致。
- 不处理申报确认。

### 5.3 申报准备

职责：

- 按季度形成增值税及附加申报准备。
- 汇总当期应进入申报的销项蓝票不含税金额。
- 汇总当期红票冲减金额。
- 确认本期是否存在未开票收入需要计入申报。
- 处理前期已申报未开票收入在本期补开发票后的冲抵。
- 判断季度不含税销售额是否低于 300,000 元免税阈值。
- 形成可进入税务办理的申报准备结果。

不承担：

- 不做发票和流水的详细匹配操作。
- 不把内部票款差异作为申报阻断。
- 不处理社保、公积金、个税缴纳。
- 不上传申报回执或缴款回单。

### 5.4 税务办理

职责：

- 承接已确认的申报准备结果。
- 提供真实电子税务局办理入口。
- 记录去办理、上传申报回执、上传缴款回单、完成办理。
- 回填实际申报销售额、实际增值税、实际附加税、实际缴款金额。

不承担：

- 不重新编辑发票台账。
- 不重新修改申报准备事项。
- 不显示内部关联流水细节。

## 6. 申报口径硬切规则

### 6.1 申报销售额

字段口径：

- 页面文案统一为 `不含税申报销售额`。
- 蓝字销项发票使用发票不含税金额。
- 红字发票使用负数不含税金额冲减。
- 未开票收入如果计入本期，必须形成单独确认记录。
- 前期已申报未开票收入后续开票，本期应从申报销售额中冲抵，避免重复申报。

计算结构：

```text
本期不含税申报销售额
= 蓝字销项发票不含税金额
+ 红字发票不含税金额
+ 本期确认计入的未开票收入不含税金额
- 前期已申报未开票收入本期补开发票冲抵金额
```

### 6.2 季度免税判断

```text
如果 本期不含税申报销售额 <= 300,000 元
则 预计增值税 = 0
预计附加税 = 0
申报准备显示：符合季度 30 万以下免税口径
```

```text
如果 本期不含税申报销售额 > 300,000 元
则 预计增值税 = 本期不含税申报销售额 * 当期适用征收率
预计附加税 = 预计增值税 * 当期附加税费口径
最终金额以电子税务局回填为准
```

说明：

- `300,000 元` 为本项目当前固定参数。
- 阈值判断基于季度合计，不基于单月。
- 当期适用征收率不要写死在页面文案中，应来自系统税务口径配置或申报准备计算模型。
- 如存在不适用免税的特殊发票或特殊收入，应在申报准备中单独分列，不能混入 300,000 元免税判断里直接归零。
- 如果电子税务局给出与系统测算不同的结果，系统保留测算结果作为准备记录，但最终状态和金额以电子税务局回填为准。

### 6.3 红字发票

红字发票不是“随便少报收入”。它应关联原蓝字发票。

处理规则：

- 红字发票必须在发票匹配中关联原蓝字发票。
- 原蓝字发票可以是当期发票，也可以是历史期间发票。
- 一个红字发票只关联一个原蓝字发票。
- 一个原蓝字发票可以被多张红字发票部分冲减，但累计冲减金额不能超过原蓝字发票金额。
- 未关联原蓝字发票的红字发票，是申报准备硬阻断。

### 6.4 未开票收入

未开票收入是“已经发生纳税义务，但还没开发票”的收入。

处理规则：

- 只能从已复核收入流水中选择。
- 可以选择 `计入本期` 或 `暂不计入本期`。
- 计入本期后，流水增加 `未开票已申报` 状态。
- 后续开票时，发票匹配进入 `前期未开票后续开票` 待办。
- 后续开票确认后，该发票在当前申报周期中冲抵，不再重复增加申报销售额。
- 暂不计入本期的流水不进入本期申报准备结果，但要保留待后续处理状态。

### 6.5 发票与业务确认匹配

匹配规则：

- 普通发票和应收应付或业务确认事实可以多对多。
- 发票金额和匹配业务可用金额必须能够严谨对应。
- 不允许在匹配环节手动改金额。
- 需要部分占用业务确认金额时，应由业务来源或拆分逻辑产生明确可用金额，而不是在发票匹配页临时输入金额。
- 已确认的应收应付或业务确认事实才能作为普通发票匹配候选。
- 已完全用于发票匹配的业务确认事实，不再作为同类候选重复出现。
- 已复核收入流水只用于未开票收入申报确认和后续开票关闭，不作为普通发票匹配候选。

## 7. 申报准备硬阻断与风险提示

### 7.1 硬阻断

以下事项未完成时，不允许进入税务办理：

| 事项 | 原因 | 处理模块 |
|---|---|---|
| 销项发票未导入完整 | 无法确定开票销售额 | 发票台账 |
| 红字发票未关联原蓝票 | 无法确认冲减依据 | 发票匹配 |
| 未开票收入未选择计入或暂不计入 | 无法确定本期申报销售额 | 申报准备 |
| 前期未开票后续开票未确认 | 可能导致重复申报收入 | 发票匹配 |
| 最终申报口径未确认 | 未形成本期申报准备结果 | 申报准备 |

### 7.2 风险提示

以下事项需要提示，但不阻断申报准备进入税务办理：

| 事项 | 说明 | 呈现方式 |
|---|---|---|
| 已开票未收款 | 税务上已开票通常已形成申报义务，内部继续跟进应收 | 风险提示 |
| 已收款未开票但暂不计入 | 保留后续处理风险 | 风险提示 |
| 发票与流水金额不一致 | 内部核对问题，不直接改变申报发票金额 | 风险提示 |
| 流水未复核 | 资金事实待确认，不直接改变已导入发票事实 | 风险提示 |

## 9. 页面硬切

### 9.1 发票台账

页面结构：

- 顶部指标按月度筛选。
- `月度台账` 表格：每行一个月份和发票方向。
- `申报周期` 表格：每行一个季度和发票方向。
- 抽屉展示当期发票明细。
- 导入记录使用统一的预览/下载组件。

字段收紧：

- 明细表不展示普通收支流水匹配明细。
- 明细表展示发票号、对象、开票日期、不含税金额、税额、价税合计、票据状态、匹配状态。

### 9.2 发票匹配

页面结构：

- 待处理列表。
- 已完成列表。
- 抽屉中选择候选流水或原蓝票。
- 不按月份作为主视角。

操作：

- 蓝票匹配收入流水。
- 红票关联原蓝票。
- 前期未开票后续开票确认冲抵。
- 撤销匹配后回到未匹配状态。

### 9.3 申报准备

页面结构：

- 按季度呈现。
- 顶部指标展示 `不含税申报销售额`、`免税阈值`、`预计增值税`、`预计附加税`、`准备状态`。
- 准备项区分 `必须处理` 和 `风险提示`。
- 未开票收入处理在申报准备抽屉内完成。

操作：

- 未开票收入选择已复核收入流水。
- 对每条未开票收入选择 `计入本期` 或 `暂不计入本期`。
- 全部必须处理项完成后，允许确认申报准备结果。
- 确认后进入税务办理。

### 9.4 税务办理

页面结构：

- 只呈现待办理事项、办理状态、申报期限、缴款期限、回执文件、操作记录。
- 增值税及附加事项引用申报准备结果。

操作：

- `去办理` 和 `上传回执` 同时存在。
- 上传申报回执后，允许填写实际申报结果。
- 上传缴款回单后，允许完成事项。

## 10. Mock 数据治理

必须覆盖以下场景：

| 场景 | 目的 | 示例 |
|---|---|---|
| 低于 30 万免税 | 验证季度免税判断 | Q2 不含税销售额 151,700 元，预计增值税 0 |
| 超过 30 万应税 | 验证超过阈值测算 | Q3 不含税销售额 362,000 元，预计有增值税 |
| 红票未关联 | 验证硬阻断 | 1 张红票未关联原蓝票，不可进入税务办理 |
| 未开票收入计入 | 验证本期申报 | 已复核收入 5,600 元，选择计入本期 |
