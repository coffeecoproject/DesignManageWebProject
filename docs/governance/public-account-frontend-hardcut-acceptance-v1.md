# 对公账户前端硬切验收 v1

## 范围

本轮仅处理前端对公账户主数据、账套期初、收付款、税费、银行对账及会计辅助核算契约，不新增审批流，不涉及后端持久化、网银直连或生产银行数据。

## 业务边界

- 对公账户配置只维护银行身份、账户能力、默认承接和启停状态，不保存会计期初余额。
- 银行存款期初余额统一来自账套初始化科目 `1002`，并按对公账户辅助核算拆分。
- 银行账号、账户户名和开户行构成稳定银行身份；账户已有期初余额、流水或银行记录后不得原地改写。
- 账户停用只影响后续新业务选择；历史流水、凭证、总账和经营汇总继续读取业务事实保存的账户 ID 与快照。
- 税费缴款和退税必须显式选择符合方向的启用账户，默认账户只负责预选，不替代实际选择结果。
- 银行导入首版只接受单账户 CSV。文件账号必须与页面所选完整账号一致，跨账户文件直接阻断，不按页面选择覆盖文件内容。
- 银行存款凭证行和总账分录必须同时保留 `对公账户` 辅助核算范围和稳定账户 ID。

## 门禁

- 文档门禁：本文件明确账户身份、会计余额、业务选择和历史快照边界。
- 自动门禁：`corepack pnpm typecheck`、`corepack pnpm test:web`、`corepack pnpm build:web`、`corepack pnpm ai-native:check`。
- 证据门禁：PA-01 至 PA-14 的身份、金额、导入和辅助核算结果必须有自动测试或现有领域状态门禁，不能仅以页面可见作为通过依据。

## 后端接入边界

后端接入时应持久化完整银行账号的受控展示值、稳定账户 ID、不可变业务快照和 `1002 + 对公账户辅助 ID` 的会计维度。银行文件应在服务端重新解析、校验文件摘要与幂等键；权限、账号脱敏、文件病毒扫描和审计不能依赖本轮前端实现。
