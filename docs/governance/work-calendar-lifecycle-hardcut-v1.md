# 工作日历生命周期前端硬切方案 v1

## 1. 范围与边界

本轮只处理前端领域契约和交互，不进入后端 API、数据库、权限执行、定时调度或持久化。

覆盖：

- 工作日历与法定节假日的生效版本；
- 公司默认工作日历的生效期间；
- 人员适用日历的任职记录与异动；
- 考勤月报、薪酬、绩效对生效日历的消费；
- 任务候选人的容量提示；
- 2026 年法定节假日种子数据。

## 2. 已确认业务规则

1. 工作日历规则按生效日期追加版本，不覆盖历史版本。
2. 法定节假日按年度保留修订记录；2026 年种子采用国务院公布的放假调休日期。
3. 全职人员建档时确定初始日历；建档后通过 `工作日历变更` 异动调整，档案维护只读。
4. 人员可选择跟随公司默认日历或指定日历；指定日历失效时不得静默回退到任意模板。
5. 休息日上的请假保留原始记录，但不计入薪酬考勤扣减。
6. 考勤月报确认时冻结有效工作日、请假扣减、调休和日历名称；后续配置变更不得改写已确认月份。
7. 任务截止时间是任务事实。执行人日历、请假冲突和可用工时不足只产生提示，不修改截止时间，也不阻止分配。
8. 人员关系无效、无任务权限或能力不匹配仍是任务分配硬阻断。
9. 非默认且已启用的工作日历可从指定日期起设为公司默认；跟随默认的人员从生效日起切换，指定日历人员不变。
10. 默认切换不得覆盖历史；当前默认和已排期的未来默认均不可停用。
11. 公司默认工作日历从 `2025-01-01` 建立历史基线，覆盖现有最早全职任职数据；基线前日期不做静默回退。
12. 规则版本、启停期间和默认期间必须是合法且不重叠的时间轴；发生歧义时解析失败，不按数组顺序猜测。
13. 任务工时和绩效反馈期限按每个自然日重新解析当日有效默认日历或人员日历，跨版本、跨默认和跨任职变更时不得沿用起始日规则。
14. 工作日历停用检查同时覆盖在职人员当前及未来的指定日历任职记录。
15. 年度法定节假日调整通过新修订和生效日期追加，不直接覆盖已生效安排；未来修订不得提前改变当前投影。
16. 同一年度的修订生效区间必须连续且不重叠，修订只能在当前日期及以后生效，跨年度修订必须建立新的年度配置。

## 3. 前端领域结构

- `WorkCalendarRow.versions`：日历规则生效版本。
- `WorkCalendarRow.statusPeriods`：日历启停生效期间；停用只影响生效日及以后，不抹除历史日期。
- `WorkCalendarRow.defaultPeriods`：公司默认日历生效期间；`isDefault` 仅作为当前日期的展示投影。
- `companyDefaultWorkCalendarValue`：人员“跟随公司默认”选项值，与任何具体工作日历 ID 分离。
- `AnnualExceptionConfigRow.revisions`：年度节假日修订记录。
- `AnnualExceptionRevision.effectiveFrom/effectiveTo`：年度修订的有效区间；业务消费者按业务日期解析唯一有效修订。
- `AnnualExceptionConfigRow.statusPeriods`：年度配置启停期间；停用不抹除历史日期的法定节假日。
- `PeopleMember.workCalendarAssignments`：人员适用日历任职记录。
- `AttendanceMonthlyConfirmationRecord.snapshot`：已确认考勤月报快照。
- 任务候选结果：`blockers` 仅承载资格问题，`warnings` 承载日历、请假和容量问题。

前端代码边界：

- `workCalendarTypes.ts`：领域类型与枚举。
- `workCalendarSeedData.ts`：默认模板、官方节假日种子和演示数据。
- `annualExceptionModel.ts`：年度节假日修订解析、校验和追加规则。
- `workCalendarRules.ts`：按业务日期消费工作日历和年度修订。
- `WorkCalendarState.tsx`：前端状态编排，不再承载年度种子与类型定义。

## 4. 验收矩阵

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| WC-01 | 2026 法定节假日 | 元旦、春节、清明、劳动节、端午、国庆及调休工作日与官方安排一致 |
| WC-02 | 日历规则变更 | 新版本只从生效日开始使用，生效日前仍解析旧版本 |
| WC-03 | 指定日历缺失 | 显示缺失/产生提示，不回退到数组第一条日历 |
| WC-04 | 人员日历变更 | 通过人事异动产生前后任职记录，支持月中生效 |
| WC-05 | 档案维护 | 已建档人员不能在档案编辑中直接改日历 |
| WC-06 | 休息日请假 | 保留请假时长，计薪有效请假为 0，薪酬扣减为 0 |
| WC-07 | 考勤确认快照 | 修改或停用日历后，已确认月份仍保持原计算结果 |
| WC-08 | 下游失效 | 未发放月份日历/考勤变化撤销考勤确认并使薪酬来源失效；已发放月份阻断 |
| WC-09 | 任务容量不足 | 计划 40 小时、可用约 32 小时时允许选择并显示警告 |
| WC-10 | 任务资格阻断 | 关系无效、无任务权限或能力不匹配时不可选择 |
| WC-11 | 默认日历切换 | 生效日前使用旧默认，生效日起使用新默认 |
| WC-12 | 指定日历隔离 | 公司默认切换不改变明确指定日历的人员 |
| WC-13 | 默认日历停用约束 | 当前默认及已排期未来默认不可停用；停用日历不可设为默认 |
| WC-14 | 历史默认基线 | 2025 年已入职且跟随默认的人员可解析公司默认日历 |
| WC-15 | 未来规则投影 | 未来规则保留在版本时间轴，但生效日前列表和详情仍展示当前规则 |
| WC-16 | 跨日历计算 | 任务工时和绩效反馈期限跨生效日时逐日使用对应日历 |
| WC-17 | 指定日历停用约束 | 当前或未来任职记录引用日历时不可停用，已结束人员与历史任职不阻断 |
| WC-18 | 年度节假日未来修订 | 修订保留在时间轴，生效日前仍解析旧修订，生效日起解析新修订 |
| WC-19 | 年度修订区间 | 追加修订自动关闭上一修订，重叠、无效日期和跨年度生效均被拒绝 |
| WC-20 | 年度修订页面 | 列表和工作日历摘要展示当前有效修订；抽屉展示生效日期及完整修订记录 |
| WC-21 | 年度配置停用 | 停用只影响生效日及以后，历史考勤、任务和绩效仍可解析原法定节假日 |

## 5. 门禁

- 自动门禁：`typecheck`、`test:web`、`lint`、`build:web`、`ai-native:check`、`git diff --check`。
- 证据门禁：WC-01 至 WC-21 必须由领域测试或静态契约覆盖。
- 当前边界：前端状态刷新后不持久，不宣称生产级历史版本、并发控制、服务端鉴权或审计不可篡改。
