# 工作日历生命周期前端硬切方案 v1

## 1. 范围与边界

本轮只处理前端领域契约和交互，不进入后端 API、数据库、权限执行、定时调度或持久化。

覆盖：

- 工作日历与法定节假日的生效版本；
- 人员适用日历的任职记录与异动；
- 考勤月报、薪酬、绩效对生效日历的消费；
- 任务候选人的容量提示；
- 2026 年法定节假日种子数据。

## 2. 已确认业务规则

1. 工作日历规则按生效日期追加版本，不覆盖历史版本。
2. 法定节假日按年度保留修订记录；2026 年种子采用国务院公布的放假调休日期。
3. 全职人员建档时确定初始日历；建档后通过 `工作日历变更` 异动调整，档案维护只读。
4. 人员可选择跟随公司默认日历或指定日历；指定日历失效时不得静默回退到任意模板。
5. 休息日上的请假保留原始记录，但不计入薪酬考勤扣减。
6. 考勤月报确认时冻结有效工作日、请假扣减、调休和日历名称；后续配置变更不得改写已确认月份。
7. 任务截止时间是任务事实。执行人日历、请假冲突和可用工时不足只产生提示，不修改截止时间，也不阻止分配。
8. 人员关系无效、无任务权限或能力不匹配仍是任务分配硬阻断。

## 3. 前端领域结构

- `WorkCalendarRow.versions`：日历规则生效版本。
- `AnnualExceptionConfigRow.revisions`：年度节假日修订记录。
- `PeopleMember.workCalendarAssignments`：人员适用日历任职记录。
- `AttendanceMonthlyConfirmationRecord.snapshot`：已确认考勤月报快照。
- 任务候选结果：`blockers` 仅承载资格问题，`warnings` 承载日历、请假和容量问题。

## 4. 验收矩阵

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| WC-01 | 2026 法定节假日 | 元旦、春节、清明、劳动节、端午、国庆及调休工作日与官方安排一致 |
| WC-02 | 日历规则变更 | 新版本只从生效日开始使用，生效日前仍解析旧版本 |
| WC-03 | 指定日历缺失 | 显示缺失/产生提示，不回退到数组第一条日历 |
| WC-04 | 人员日历变更 | 通过人事异动产生前后任职记录，支持月中生效 |
| WC-05 | 档案维护 | 已建档人员不能在档案编辑中直接改日历 |
| WC-06 | 休息日请假 | 保留请假时长，计薪有效请假为 0，薪酬扣减为 0 |
| WC-07 | 考勤确认快照 | 修改或停用日历后，已确认月份仍保持原计算结果 |
| WC-08 | 下游失效 | 未发放月份日历/考勤变化撤销考勤确认并使薪酬来源失效；已发放月份阻断 |
| WC-09 | 任务容量不足 | 计划 40 小时、可用约 32 小时时允许选择并显示警告 |
| WC-10 | 任务资格阻断 | 关系无效、无任务权限或能力不匹配时不可选择 |

## 5. 门禁

- 自动门禁：`typecheck`、`test:web`、`lint`、`build:web`、`ai-native:check`、`git diff --check`。
- 证据门禁：WC-01 至 WC-10 必须由领域测试或静态契约覆盖。
- 当前边界：前端状态刷新后不持久，不宣称生产级历史版本、并发控制、服务端鉴权或审计不可篡改。
